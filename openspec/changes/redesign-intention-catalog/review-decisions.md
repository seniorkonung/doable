## F3 · Low — Delta `intention-management` повторяет обязательства, у которых есть свой владелец, и держит сценарии пустой выдачи каталога в чужом требовании

- **Решение:** Устранить
- **Как устранить:** Устранить через openspec-update-change без изменения кода, поведения продукта и без новых задач; правится только delta openspec/changes/redesign-intention-catalog/specs/intention-management/spec.md. 1) В добавленном требовании «Кнопка фильтра по тегам в поиске намерений» оставить собственные обязательства: четыре контекста поиска, показ условий кнопкой фильтра (без условий — только значок, при условиях — выделение и число, каждое обязательное и исключённое условие считается одним), доступное название с указанием фильтра по тегам и числа условий, отсутствие условий под полем поиска, открытие панели тегов в режиме фильтра кнопкой. Повторы чужих обязательств (одно условие на тег, немедленное применение, отличие пустой выдачи по условиям от пустого охвата, запрет изменять теги, несохранение условий после закрытия поиска) заменить ссылками на требования-владельцы: «Условия по тегам в панели тегов», «Согласованность параметров совместного поиска», «Пустая выдача поиска намерений», «Совместная фильтрация намерений по названию и тегам», «Самостоятельное состояние открытых страниц поиска намерений». Удалить сценарий «Пустая выдача по условиям отличается от пустого охвата»; сценарий «Кнопка фильтра показывает число условий» оставить. 2) Сценарии состава сообщений пустой выдачи каталога «Пустой активный каталог», «Пустой архив», «Пустой охват всех намерений», «Фильтр без совпадений» перенести из «Состояний получения данных» в «Пустую выдачу поиска намерений», согласовав с её текстом (третья причина для каталога во всех охватах, первая причина по названию). 3) В «Состояниях получения данных» оставить только обязательство, что успешная пустая выдача явно показана и отличима от загрузки и ошибки, со ссылкой на «Пустую выдачу поиска намерений» за составом; сценарий загрузки и сценарии ошибок сохранить. Проверить ссылки tasks.md и plan.md на перенесённые сценарии и validate --strict.
