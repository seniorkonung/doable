## F1 · Medium — Возврат типа каталога при замене графа в фазе 2 ничем не проверяется

- **Решение:** Устранить
- **Как устранить:** Выбран вариант A: модельная проверка в задаче 2.5. Исход: в фазе 2 есть проверка, которая падает, если после смены поколения графа охват, тип, порядок или фильтр названия каталога не вернулись к начальным значениям. Изменить только tasks.md, задачу 2.5, которая ещё не выполнена. В критерии приёмки добавить: после смены поколения графа выбор параметров каталога и новый запрос первой порции несут начальные значения: охват «Активные», тип «Все», `createdAtDescending`, пустой фильтр названия. Так проверка отличает этот сброс от `resetShowParameters()`, который фильтр названия и условия по тегам сохраняет. В перечень проверок 2.5 добавить случай в `test/intention/presentation/catalog/intention_catalog_view_model_test.dart`: исходно охват «Все», тип «Действия», порядок по названию, фильтр «бег»; затем смена поколения через `currentGraphGenerationProvider`; тип читается из модели, потому что прежняя страница его не показывает. Команда проверки 2.5 не меняется: этот файл в неё уже входит. Условия по тегам в случай не входят: они принадлежат `IntentionTagConditionsViewModel`, 2.5 их не меняет, а `app_shell_graph_generation_test.dart` покрывает их в 2.6. Новых задач не добавлять, порядок задач не менять, plan.md, design и спецификации не менять. Проверку навигации из фазы 4 («тип сбрасывается после импорта») этот случай не заменяет, она остаётся. Поведение приложения не меняется.

Остальные команды, критерии приёмки и порядок задач не менять, новых задач не добавлять, plan.md, design и спецификации не менять. Поведение приложения не меняется.
