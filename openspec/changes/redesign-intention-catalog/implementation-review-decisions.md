## F1 · Low — Сценарий создания выводит позицию списка из порядка прокруток в дереве

- **Решение:** Устранить
- **Как устранить:** Итог: сценарий создания читает позицию списка выдачи по самому списку и сравнивает остальные прокрутки страницы без предположения о порядке прокруток в дереве; поведение приложения и ожидания сценария не меняются. Выбранный вариант: добавить в конец Phase 3 файла tasks.md новую задачу 3.8 (после всех существующих задач) с критериями приёмки и проверкой и выполнить её. В test/support/intention_catalog_controls.dart появляется один новый шаг: смещения вертикальных прокруток страницы каталога, кроме списка выдачи; список исключается по самому положению intentionCatalogListPosition, а не по месту в дереве. В test/app/intention_creation_sheet_integration_test.dart функция _catalogView берёт list из intentionCatalogListPosition(tester).pixels, а outer из нового шага; offsets.last, offsets.sublist и комментарий о том, что список стоит в дереве последним, удаляются. Проверка: новая строка сдвинула список, остальные прокрутки и видимые строки остались на местах, сохраняется без ослабления. Ограничения: lib/ не меняется, новых сценариев нет, существующие вызовы shownIntentionCatalogOffsets не меняются, из документации этого шага убирается упоминание порядка дерева, потому что на порядок больше никто не опирается. Проверка задачи: flutter test для test/app/intention_creation_sheet_integration_test.dart и flutter analyze через mise exec --no-deps. Ожидаемые артефакты: tasks.md, test/support/intention_catalog_controls.dart, test/app/intention_creation_sheet_integration_test.dart.

## F2 · Low — Проверка доступности берёт ожидаемое название поля из проверяемой семантики

- **Решение:** Устранить
- **Как устранить:** Итог: проверка доступности берёт ожидаемое название поля названия каталога из источника, не зависящего от проверяемой семантики, а смена подписи поля меняет только общий файл шагов; поведение приложения не меняется. Выбранный вариант: добавить в конец Phase 3 файла tasks.md новую задачу 3.9 (после всех существующих задач, включая 3.8) с критериями приёмки и проверкой и выполнить её. В test/intention/presentation/editor/intention_creation_sheet_accessibility_test.dart локальная titleFieldName, чтение семантики через EditableText, expect(titleFieldName, isNotEmpty) и поясняющий их комментарий удаляются, а containsAll в _traversal сравнивает с intentionCatalogTitleFieldLabel(tester). Там же, в tasks.md, предложение критерия задачи 3.4 о том, что intention_creation_sheet_accessibility_test.dart берёт название поля из семантики intentionCatalogTitleField, заменяется на чтение подписи шагом intentionCatalogTitleFieldLabel; отметка выполнения 3.4 остаётся, номера задач не меняются. Ограничения: lib/ не меняется, новых шагов и сценариев нет, строка catalogFilterLabel в этом тесте напрямую не появляется, поэтому поиск из задачи 3.7 остаётся чистым. Проверка задачи: flutter test для test/intention/presentation/editor/intention_creation_sheet_accessibility_test.dart и flutter analyze через mise exec --no-deps. Ожидаемые артефакты: tasks.md (критерий 3.4 и новая задача 3.9), test/intention/presentation/editor/intention_creation_sheet_accessibility_test.dart.
