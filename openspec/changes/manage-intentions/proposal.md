## Why

Doable пока не позволяет сохранить даже корневую сущность предметной области, поэтому ни долговременный граф, ни дневной выбор не могут получить устойчивое основание. Сейчас необходимо реализовать законченный жизненный цикл намерений как первую пользовательскую вертикаль, которая проведёт реальное поведение через Flutter-интерфейс, прикладные правила и локальное постоянное хранилище без преждевременного проектирования связей и обхода графа.

## What Changes

- Добавить создание намерения с уникальным идентификатором, названием, необязательным описанием и начальной готовностью к действию, всегда равной «не готово».
- Нормализовать название удалением окружающих пробельных символов, требовать от 1 до 255 пользовательски воспринимаемых Unicode-символов и разрешить одинаковые названия у разных намерений.
- Считать полностью пробельное описание отсутствующим, но при наличии хотя бы одного непробельного символа сохранять до 4096 пользовательски воспринимаемых Unicode-символов без изменения пробелов и переносов строк.
- Добавить каталог намерений с выбираемым охватом: активные намерения по умолчанию, архивированные намерения либо все существующие намерения независимо от архивного состояния; из каждого охвата позволять открыть подробные данные намерения.
- Добавить регистронезависимую фильтрацию каталога по вхождению в название с точным общим количеством совпадений; окружающие пробелы фильтра игнорировать, ограничить нормализованный фильтр 255 пользовательски воспринимаемыми Unicode-символами и объяснять превышение без выполнения поиска, а теги, ранжирование и полнотекстовый поиск не добавлять.
- Выдавать каталог ограниченными курсорными порциями и автоматически добавлять следующую порцию при приближении к концу уже загруженного списка; размер порции и порог упреждающей загрузки хранить в единой инженерной конфигурации.
- Позволять сортировать каталог по сохранённым показаниям системных часов при создании или последнем изменении в возрастающем или убывающем направлении; по умолчанию использовать убывающее значение времени создания, не обещая точного совпадения с фактической хронологией после перевода часов.
- Добавить изменение названия, описания и готовности к действию для активных и архивированных намерений; переход в состояние действия выполнять только отдельным явным решением пользователя с объяснением критериев однодневной выполнимости и операционной понятности.
- Добавить архивирование и восстановление намерения без отождествления архивирования с выполнением или удалением.
- Добавить необратимое физическое удаление активного или архивированного несвязанного намерения без обязательного предварительного архивирования, но только после отдельного явного подтверждения.
- Сохранять намерения, время их создания, время последнего успешного изменения и все изменения состояния локально между запусками приложения.
- Создавать новую локальную схему и применять её миграции атомарно с безопасным повтором после прерывания, отличать повреждение SQLite от временной недоступности и не выполнять полный аудит поискового индекса при каждом обычном открытии уже совместимого хранилища.
- Ограничить обещание локальной долговечности одной установкой приложения: на каждой поддерживаемой платформе исключать локальное хранилище из системного cloud backup и переноса данных между устройствами; после удаления приложения, очистки его данных или утраты устройства прежние данные в новой установке не восстанавливаются.
- Сохранить независимые от SQLite идентификаторы и storage-neutral seam прикладного модуля, чтобы будущая управляемая синхронизация могла подключиться без зависимости UI от локального adapter; учётные записи, удалённое хранилище, транспорт, разрешение конфликтов и само поведение синхронизации в этот change не добавлять.
- Локализовать все системные строки новой возможности на русский и английский языки: использовать системную локаль, выбирать английский для остальных локалей и не переводить пользовательские названия и описания. Ручной переключатель языка не добавлять.
- Обеспечить для новой возможности необходимые состояния загрузки, пустого результата и ошибок, доступность интерфейса и проверяемое поведение.
- Не добавлять в этот change долговременные связи, теги, ранжированный или полнотекстовый поиск, связи «я сегодня», пути выбора, выполнение дневного выбора или облачную синхронизацию.
- Сохранить capability, предметный и прикладной modules платформонезависимыми; в текущем change реализовать и проверить только Android host adapter, не заявляя поддержку или готовность поставки других платформ.
- Не публиковать приложение и не настраивать канал распространения, store metadata, production signing keys или секреты сборки; release-mode APK используется только для автоматизированной CI-проверки и локальной проверки поведения и manifest.

## Capabilities

### New Capabilities

- `intention-management`: создание, ограниченный просмотр с охватом, фильтрацией, сортировкой и автоматической курсорной подгрузкой, изменение, классификация по готовности к действию, архивирование, восстановление, физическое удаление и сохранение результатов операций с намерениями с русским и английским интерфейсом.
- `local-data-lifecycle`: открытие и локальная долговечность данных в пределах одной установки приложения, атомарное создание и версионируемая миграция схемы, совместимость версий, классификация повреждения, ограниченная стоимость обычного bootstrap recovery и политика системного backup/transfer для поддерживаемых platform adapters.

## Impact

- Изменятся Flutter-приложение и его навигация, предметный и прикладной слои, локальное хранение данных, локализация и тестовый набор.
- Появится постоянная локальная модель намерения и механизм миграций, на которые будут опираться последующие change долговременных связей и дневного выбора.
- Общий lifecycle локальных данных получит собственную capability, а `IntentionRepository` останется storage-neutral seam: текущий Drift adapter не станет частью interface для UI и будущих источников данных.
- Capability и Flutter/Dart modules не будут зависеть от Android SDK, путей, разрешений или platform channels; Android-specific storage, backup, manifest и release evidence останутся в host adapter.
- Потребуются зависимости и конфигурация для выбранных в design локального хранилища, управления состоянием и Flutter-локализации.
- Локальная схема получит индекс названий SQLite FTS5 для регистронезависимой фильтрации по подстроке без загрузки всех намерений в память.
- Появится обязательный GitHub Actions PR gate для воспроизводимой генерации, проверки committed artifacts, анализа, тестов, Android release-mode сборки и строгой OpenSpec-валидации.
- Изменений внешних API, учётных записей, облачных сервисов и синхронизации данных не будет.
