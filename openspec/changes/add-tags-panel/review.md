## Findings

### F7 · Low — Сохранение строк и прокрутки при обновлении панели не закреплено в задачах

- **Evidence:** Требование «Согласование панели тегов с подтверждёнными изменениями» в [tag-management](specs/tag-management/spec.md) гласит: «Обновление показанного списка тегов MUST сохранять строки и прокрутку». Сценарий «Фоновое обновление сохраняет список» требует того же и при отказе обновления. Задача 2.8 проверяет этот сценарий на модели, где прокрутки нет. Критерии задачи 2.10 называют `Notice` с «Повторить» над неактуальным списком, но не сохранение прокрутки. В её проверке нет ни обновления, ни его отказа, ни повтора. Прежний каталог проверял это на экране: «фоновое обновление и его повтор сохраняют выбор и прокрутку каталога» в `test/tag/presentation/catalog/tag_catalog_page_test.dart`. Обновление достижимо двумя путями. Модель задачи 2.8 перечитывает снимок на каждый пакет, который не объясняет локально. После отказа обновления человек запускает чтение кнопкой «Повторить».
- **Impact:** Панель может сбрасывать прокрутку к началу, когда над списком появляется `Notice` или список пересобирается после обновления. Такая панель пройдёт все проверки фазы, хотя нарушает обязательство спецификации, и в длинном каталоге каждое обновление будет возвращать человека к началу.
- **Required change:** Критерии задачи 2.10 должны требовать сохранения показанных строк и положения прокрутки при фоновом обновлении, его отказе с `Notice` и повторе. Проверка задачи подтверждает это на панели с каталогом длиннее экрана.

### F8 · Low — Состояние «Теги не найдены» в панели недостижимо

- **Evidence:** Задача 2.10 перечисляет «Теги не найдены» среди состояний панели. Основание — требование «Очистка поиска и отсутствие совпадений тегов» в [tag-management](specs/tag-management/spec.md): сообщение показывается при непустом запросе без совпадений, «когда создание не предлагается». По требованию «Создание тега из панели» и задаче 2.13 строка создания предлагается для любого непустого применённого запроса, которому не равно ни одно название по правилу уникальности. Это правило сравнивает целиком свёрнутые названия без окружающих пробелов, а совпадение поиска — вхождение `name.matchingKey.contains(...)` ([tag_catalog_filter.dart](../../../lib/src/tag/presentation/catalog/tag_catalog_filter.dart)). `TagName.matchingKey` сворачивает уже очищенное от пробелов название ([tag_name.dart](../../../lib/src/tag/domain/tag_name.dart)). Поэтому равенство названий влечёт и вхождение. Непустой запрос без совпадений всегда получает строку создания. Пустой запрос показывает весь каталог либо подсказку пустого каталога. При некорректном вводе применённым остаётся последний корректный запрос, так что вывод тот же.
- **Impact:** Задача 2.10 строит и локализует состояние, которое не вызывают ни ввод, ни данные. Формулировка спецификации подсказывает исполнителю и тестировщику несуществующий сценарий. Прежние каталог и выбор условия, где строки создания нет, сохраняют это сообщение до фазы 4.
- **Required change:** Нужно убрать «Теги не найдены» из состояний панели в задаче 2.10, а для панели — и из требования «Очистка поиска и отсутствие совпадений тегов». Иначе нужно назвать достижимый случай, когда при непустом запросе без совпадений строка создания не предлагается.

## Accepted risks

### AR1 · Задачи 1.2 и 1.5 требуют полных прогонов тестов вместо проверок затронутых потребителей

- **Evidence:** [Задача 1.2](tasks.md) требует `mise run check:tests -- 0 1` и `mise run check:process-tests`, задача 1.5 — повторный `mise run check:tests -- 0 1`. По [mise.toml](../../../mise.toml) и [tool/test_shard.sh](../../../tool/test_shard.sh) это все 342 обычных набора и все наборы с вложенным Flutter. [AGENTS.md](../../../AGENTS.md), Test execution scope, ограничивает проверку задачи изменёнными модулями и непосредственными потребителями, а полный `mise run check` оставляет завершению фазы — он уже есть в задаче 1.7. Поиск по `test/` показывает, что задача 1.2 затрагивает около 133 наборов: они собирают `Tag`, вставляют строки `tags` или зависят от `tag_storage_fixture.dart` и `graph_log_completeness_reference.dart`. Тегов касаются три из пяти наборов с меткой `flutter_process`.
- **Potential impact:** До проверки фазы в задаче 1.7 весь набор прогоняется ещё дважды, и около 60% наборов в этих прогонах не связаны с тегами. Сбой несвязанного набора задерживает задачу. Исполнитель получает расходящиеся указания задачи и правила репозитория.
- **Acceptance rationale:** Задача 1.2 и так затрагивает около 40% наборов, поэтому полный прогон даёт простую страховку от пропущенного потребителя при переходе общего контракта тега и при смене видимого порядка в 1.5. Её ценность человек ставит выше лишнего времени исполнения.
- **Scope and assumptions:** Только проверки задач 1.2 и 1.5 фазы 1 в их текущей формулировке. По этому решению указание задачи о полном прогоне имеет приоритет над правилом охвата для этих двух задач. Проверку фазы задачей 1.7 приёмка не меняет и не распространяется на другие задачи и фазы.
- **Reopen when:** Задачи 1.2 или 1.5 перепланируются либо меняются их проверки. Новая задача копирует полный прогон со ссылкой на эту приёмку. Правило Test execution scope или порядок исполнения задач оркестратором запрещают полные прогоны внутри задачи. Полный прогон внутри задачи не удаётся завершить.
- **Acceptance authority:** Явное решение пользователя при разрешении F4 22.10.2026: «Принять риск» — оставить полные прогоны в задачах 1.2 и 1.5 и записать остаточный риск.
- **Originating finding:** F4
- **Acceptance lifetime:** Change-scoped
