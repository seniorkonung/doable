## Findings

### F1 · Medium — Заголовок `TopBar` не называет маршрут для экранного диктора

- **Evidence:** `lib/src/design_system/components/top_bar.dart:52-54` оборачивает заголовок в `Semantics(container: true, header: true)` без `namesRoute`. На базе 40e69679b54c180cf2d50fc1ab5f328b482ce384 обе страницы поисков строили шапку через Material `AppBar` (`daily_choice_action_picker_page.dart:63`). `AppBar` во Flutter 3.47.1 (`packages/flutter/lib/src/material/app_bar.dart:1068-1080`) помечает заголовок `namesRoute: true` на Android, Fuchsia, Linux и Windows. В репозитории это общее правило для заголовков экранов: `sheet.dart:723`, `confirm_dialog.dart:99`, `intention_editor_page.dart:152`. Тест `test/design_system/top_bar_test.dart:53-75` проверяет только `isHeader`.
- **Evidence revisions:** ["40e69679b54c180cf2d50fc1ab5f328b482ce384", "c57cc8222b8d417c8c669707b237558011093dc6"]
- **Impact:** На Android при каждом открытии поиска действия или исходного намерения TalkBack больше не объявляет название экрана: у маршрута нет узла с `namesRoute`. Для пользователей экранного диктора это регресс относительно прежних поисков. Он перейдёт и на поиск участника в фазе 3 и на любой экран с `TopBar`. Потребитель не может исправить это снаружи: `TopBar` принимает заголовок готовой строкой.
- **Required outcome:** Когда открывается маршрут с `TopBar`, экранный диктор на платформах, где Flutter использует имя маршрута, объявляет текст заголовка панели. Заголовок при этом остаётся одним узлом-заголовком, а проверка компонента закрепляет это свойство.
- **Earliest source of truth:** implementation/tests
- **Affected artifacts:** ["lib/src/design_system/components/top_bar.dart", "test/design_system/top_bar_test.dart", "tasks.md: 2.8"]
