## Findings

### F5 · Medium — Проверка задачи 2.9 требует от областей нажатия 48×48, а компоненты экрана по дизайн-системе дают 44

- **Evidence:** Проверка задачи 2.9 в `tasks.md` требует «правила доступности Android для областей нажатия, их подписей и контраста текста»; в решении 10 `design.md` строка «Экран выбора» называет «доступные правила Android». В `flutter_test` правило `androidTapTargetGuideline` требует не меньше 48×48 от каждого узла с нажатием, если он не касается края экрана, а `iOSTapTargetGuideline` — не меньше 44×44 (`packages/flutter_test/lib/src/accessibility.dart`, Flutter 3.47.1). У компонентов экрана области меньше 48. По задаче 2.8 и решению 8 крестик `TopBar` занимает область 44, а `FilterButton` — квадрат 44; так же требуют README этих компонентов и токен `tap-min` = 44 в `context/doable-design-system/tokens.json` и `DoableMetrics.tapMin`. Высота существующего `SearchField` равна `tapMin` (`lib/src/design_system/components/search_field.dart`, `test/design_system/search_field_test.dart:28`), а его крестик очистки по README `SearchField` и в `_ClearButton` занимает 32. В поиске исходного намерения строка намерения без описания, тегов и готовности по отступам макета `ActionPicker.dc.html` имеет высоту 11 + 22 + 12 = 45. Проверки проекта уже сверяют цели модуля основ с пределом 44, а не 48. Проверка панели тегов при пустом поле поиска применяет `iOSTapTargetGuideline` с комментарием «Цели касания панели из модуля основ не меньше 44 точек» (`test/intention/presentation/intention_tag_search_accessibility_test.dart:452-455`). Проверки компонентов сравнивают области с `DoableMetrics.tapMin`.
- **Impact:** Проверка задачи 2.9 в нынешней формулировке не пройдёт. Кнопка фильтра и поле поиска — цели 44 вдали от края экрана, а строка без описания и тегов имеет высоту 45. Исполнителю придётся самому выбирать: ослабить проверку вопреки тексту задачи или увеличить области нажатия компонентов модуля основ вопреки решению 8, README и `tap-min`. Увеличение затронет и `SearchField`, общий с панелью тегов. В первом случае задача выполнена не по контракту, во втором — переделываются задачи 2.4 и 2.8 и экран расходится с дизайн-системой.
- **Required change:** Согласовать проверку областей нажатия экрана выбора с областями его компонентов в решении 10 дизайна и в проверке задачи 2.9. Цели модуля основ проверяются по `tap-min` (44, `iOSTapTargetGuideline`), как в проверке панели тегов. Проверка выполняется при пустом поле поиска: крестик очистки `SearchField` по своему README занимает 32. Проверки подписей целей и контраста текста сохраняются, а области нажатия в задачах 2.4 и 2.8 и у `SearchField` не меняются.
