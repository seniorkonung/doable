## Findings

### F1 · Medium — Перенос проверок панели не охватывает навигацию по тегам

- **Evidence:** Решение 5 [дизайна](design.md) и задача 3.14 [пакета](tasks.md) заменяют `NavigationBar` собственной раскладкой `AppNavigationBar`. Подготовительные задачи 3.12–3.13 перечисляют перенос проверок оболочки, геометрии и Widgetbook; задачи 3.16–3.20 переносят входы создания. Между тем `test/app/tag_navigation_primary_navigation_app_scenarios.dart:124` требует три доступных `NavigationDestination`, а строка 131 нажимает пункт через этот тип и индекс. Это подключённая часть `test/app/tag_navigation_app_lifecycle_test.dart`. Аналогичное требование трёх `NavigationDestination` находится в `test/tag/presentation/navigation/tag_navigation_primary_navigation_scenarios.dart:23`, подключённом к `tag_navigation_page_test.dart`. Оба набора входят в сохранённый контракт задачи 1.5, но ни одна новая задача не охватывает их адаптацию. Первый попадает в запуск всего `test/app` задачи 3.23, второй — в полный `mise run check` задачи 3.28; обе задачи являются только проверками.
- **Impact:** При предусмотренной замене панели эти проверки будут находить ноль старых виджетов вместо трёх и перестанут выполнять реальные переходы. Поэтому заданный пакет не обеспечивает прохождение собственных контрольных точек без незапланированного исправления тестов. Удаление утверждений или сохранение фиктивных старых виджетов ради прохождения ослабит доказательство сохранности выдачи, возврата, сброса истории и доступности панели в состояниях чтения тега.
- **Required change:** Включить перенос обоих наборов в незавершённую работу Phase 3 до замены панели, сейчас задачи 3.14, после необходимых подготовительных задач и строго в порядке файла. Использовать наблюдаемое назначение пунктов и фактические нажатия с сохранением прежних проверок состояния, истории и доступности; подтвердить оба родительских тестовых файла на прежней панели и после замены. Завершённую задачу 1.5 и остальные блоки Phase 1–2 не изменять. Итоговые контрольные точки должны проверять уже выполненный перенос.

Контракт включает постановку каждого неизменяемого значения до асинхронной границы, последовательную полную атомарную замену без объединения, продолжение после отказа и отсутствие отката интерфейса. Отсутствие файла, повреждённое содержимое, отказ чтения и бросающий диагностический получатель охвачены. Сверены действующие AppRuntime, диагностическая граница, закреплённый транзитивный path_provider, Android backup/transfer-исключения и команда проверки итогового privacy manifest. Миграция схемы графа не требуется.

Проверки различают нажатие, долгое нажатие и действие экранного диктора; смена режима не запускает создание. Учтены модальность, повторное открытие меню во время записи, независимые блокировки панелей, отмена поиска и поздний результат.
