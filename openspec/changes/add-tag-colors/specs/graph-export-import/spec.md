## MODIFIED Requirements

### Requirement: Состав файла экспорта
Файл экспорта MUST содержать весь граф намерений: активные и архивированные намерения, теги и их назначения намерениям, активные и архивированные долговременные связи и все дневные выборы вместе с их путями выбора. Для каждой сущности файл MUST сохранять её идентификатор и все данные, которые определяют соответствующие capability: название, описание, готовность к действию, архивное состояние и показания времени создания и последнего изменения намерения; название и цвет тега; тип, участников, приоритет, описание и архивное состояние долговременной связи; участников, дату, запланированное время, приоритет, выполнение, описание и путь дневного выбора. Файл MUST сохранять и все видимые пользователю порядки: последовательность создания тегов, назначений внутри тега, долговременных связей и дневных выборов.

Статистика, состояния дней и другие производные данные MUST NOT входить в файл: после импорта они вычисляются из импортированного графа. Настройки установки, в том числе режим быстрого создания, и резервные копии MUST NOT входить в файл.

Файл MUST отражать одно подтверждённое состояние графа: изменение, подтверждённое во время экспорта, MUST попадать в файл целиком либо не попадать вовсе.

#### Scenario: Импорт экспорта воспроизводит граф
- **GIVEN** граф содержит архивированное намерение, две связи «нужно» одного намерения с приоритетом P2, созданные одна за другой, дневной выбор, путь которого проходит через ныне архивированную связь, синий тег, назначенный сначала намерению А, затем намерению Б, и отдельный тег без цвета
- **WHEN** пользователь экспортирует граф и импортирует файл в другой установке
- **THEN** там доступны те же сущности с теми же идентификаторами и данными, включая синий цвет одного тега и отсутствие цвета другого, связи с P2 идут в прежнем порядке, путь дневного выбора сохранён, а навигация по тегу показывает А раньше Б

#### Scenario: Настройки установки не переносятся
- **GIVEN** в исходной установке выбран режим быстрого создания «Новый дневной выбор», а в целевой — «Новое намерение»
- **WHEN** файл экспорта исходной установки импортируется в целевую
- **THEN** в целевой установке остаётся режим «Новое намерение»

#### Scenario: Изменение во время экспорта
- **GIVEN** выполняется экспорт большого графа
- **WHEN** пользователь архивирует намерение вместе с его связями
- **THEN** файл содержит это намерение и все его связи либо в состоянии до архивирования, либо в состоянии после него

### Requirement: Формат файла экспорта
Файл экспорта MUST описывать сущности в терминах предметной области и MUST NOT зависеть от устройства локального хранилища: изменение схемы базы данных без изменения сути данных MUST NOT менять формат. Содержимое файла MUST NOT зависеть от языка интерфейса. Файл SHALL быть сжатым gzip текстом UTF-8 в формате JSON Lines, где каждая строка — один объект JSON. Первая строка SHALL быть заголовком с маркером формата Doable, версией формата, моментом экспорта и количеством записей каждого вида; далее SHALL следовать записи сущностей в таком порядке, что каждая запись ссылается только на сущности из предшествующих строк.

После первой публикации версия формата MUST меняться при каждом изменении состава или смысла данных файла и только тогда. До первой публикации базовый формат SHALL задаваться непосредственно текущим составом данных, включая цвет тега; поддержка прежних неопубликованных вариантов, их чтение и преобразование не требуются. Текущая версия приложения MUST импортировать файл любой ранее опубликованной версии формата без установки промежуточных версий приложения. Если более поздняя версия ужесточает правило данных, файл более ранней версии MUST импортироваться с тем же преобразованием, которое миграция локального хранилища применяет к уже сохранённым данным. Чтение каждой опубликованной версии MUST быть доказано автоматизированными проверками на неизменяемых эталонных файлах этой версии до признания сборки готовой.

#### Scenario: Файл давно устаревшей версии импортируется
- **GIVEN** файл экспорта создан ранее опубликованной версией приложения, вышедшей несколько версий формата назад
- **WHEN** пользователь импортирует его в текущей версии приложения
- **THEN** граф содержит все сущности, данные и порядки этого файла в текущем представлении
