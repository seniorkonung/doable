# OpenSpec Change Review: introduce-actions-and-intention-kinds

## Assessment

**Format version:** 1
**Result:** No unresolved findings
**Coverage status:** Complete
**Summary:** Повторный широкий аудит после появления `design.md`, `adr.md` с ADR-0055–ADR-0060, `plan.md` и пакета задач Фазы 1. Решения дизайна и собственные ADR согласованы со спеками, четыре фазы плана покрывают обязательства спек, а задачи Фазы 1 покрывают её исход в исполнимом порядке файла: бенчмарки переходят на действия (1.27) до удаления чтений и команд дневных выборов графом (1.28), а перенос `CalendarDate` (1.1) переводит и импорты бенчмарков. По решению пользователя требования поддержки вспомогательных технологий убраны из `action-management` и `contribution-statistics` этого изменения: требования «Локализация действий» и «Локализация статистики» сохраняют только локализацию и состояние при смене локали. Разделы Purpose канонических спек переписывает работа фаз, меняющих их поведение: задача 1.30 — `app-navigation` и `contribution-statistics`, Фаза 2 плана — `quick-creation`. Триггеры надгробий D3 создают надгробия намерения и пары после удаления по удалённой строке, без обновления надгробия пары, что совместимо с отказом в надгробии существующей сущности; ADR-0055 и задачи 1.2 и 1.6 с этим согласованы. Списки ADR в `proposal.md`, `adr.md` и задаче 1.30 называют один набор записей, которые упоминают дневные выборы вне заменяемых частей, а проверка 1.30 охватывает `docs/adr`. ADR-0058 записывает частичный пересмотр ADR-0020 для черновиков листа нового действия, а `proposal.md`, `adr.md` и индекс ADR классифицируют ADR-0020 как пересматриваемую. Ручная проверка на устройстве по решению пользователя проводится один раз после Фазы 4: Plan Constraints это фиксируют, Фаза 4 называет передачу APK с перечнем ручных проверок всего изменения, а задача 1.31 собирает APK без перечня ручных проверок. Принятых остаточных рисков нет.
**Validation:** `openspec validate introduce-actions-and-intention-kinds --strict --no-interactive` проходит. Переименования через REMOVED + ADDED вынуждены OpenSpec 1.13.0: MODIFIED не может убрать сценарий. `.openspec.yaml` объявляет `retire_capabilities: true` для опустевшей `daily-choice-management`. Изменяемые пути из задач Фазы 1 существуют в репозитории; отсутствуют только файлы, которые задачи добавляют. Пакеты задач Фаз 2–4 по схеме ещё не наступили.
