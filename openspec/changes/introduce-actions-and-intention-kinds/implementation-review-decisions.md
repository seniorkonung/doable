## F1 · Low — Повтор после отказа чтения пути теряет подтверждённые числа половин

- **Решение:** Устранить
- **Как устранить:** Устранить по варианту A (структурное исправление, выбрано пользователем вместо точечной правки retry() и вместо принятия риска). Результат: пока последнее намерение пути не меняется, любой переход черновика экрана пути, включая «Повторить» после отказа чтения пути (`PathViewModel.retry()`, ветвь `FailedPathDraft`), сохраняет подтверждённые числа половин «Нужно»/«Можно» до нового подтверждённого результата чтения, в том числе при повторном отказе. Наличие данных переключателя у черновика в загрузке и после отказа гарантирует структура состояния: убрать `path.candidates!` в `path_page.dart` и зависимость от порядка присваиваний после `PathState.withDraft` (сейчас всегда обнуляет candidates), например хранить состояние кандидатов в `LoadingPathDraft`/`FailedPathDraft` или сделать варианты `PathState` закрытыми (sealed) с ненулевыми кандидатами для этих черновиков — конкретную форму выбрать по месту, без runtime-проверок и `!`. Видимое поведение экрана в остальном не меняется. Ожидаемые изменения: `lib/src/action/presentation/path/path_state.dart`, `path_view_model.dart`, `path_page.dart`, `path_view_model.g.dart` (перегенерировать, `mise run codegen-check` должен пройти), `test/action/presentation/path/path_view_model_test.dart` — тест (название на русском): после отказа чтения пути с подтверждёнными числами и «Повторить» числа сохраняются, и при повторном отказе тоже. Существующие тесты не ослаблять. Новые задачи не добавлять (это исправление критерия выполненной задачи 2.25); если процессу нужна отслеживаемая задача, добавить её только в конец Phase 2 следующим свободным номером 2.N.

## F2 · Low — Связи в `RelationBatchAdded` никто не читает, а успех добавления разбирается дважды

- **Решение:** Устранить
- **Как устранить:** Устранить без изменения поведения. Убрать из `RelationBatchAdded` (`lib/src/long_term_relation/presentation/batch_picker/relation_batch_state.dart`) поле `relations`, сделав его маркером подтверждённого добавления без данных (обновить doc-комментарий), и разбирать исход успешного `AddLongTermRelations` (`LongTermRelationsAdded`) в одном месте в `relation_batch_view_model.dart`: `submit()` и `_finish` не должны дублировать разбор результата завершения команды. Неизменные ограничения: якорь пути (задача 2.26) получает связи из future, возвращаемого `submit()`, и получает их даже после ухода с поиска до исхода записи; поведение поиска участника для других якорей, правило `canPop`, закрытие поиска через `removeRoute` и надпись «Добавляем…» не меняются; поиск участника остаётся общим модулем (ADR-0049). Ожидаемые изменения: `relation_batch_state.dart`, `relation_batch_view_model.dart`, при необходимости `relation_batch_picker_page.dart`, перегенерированный `relation_batch_view_model.g.dart` (`mise run codegen-check` должен пройти). Существующие тесты задачи 2.26 и поиска участника должны проходить без ослабления. Новые задачи не добавлять; если процессу нужна отслеживаемая задача, добавить её только в конец Phase 2 следующим свободным номером 2.N.
