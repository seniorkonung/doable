## F1 · High — Полные проверки проекта падают: тесты потоков связей не учитывают новый выбор начальной группы

- **Решение:** Устранить
- **Как устранить:** Исправить только тесты, поведение продукта не меняется: правило задачи 3.13 (вкладка «Связи» открывает первую группу с активными связями, затем с архивированными, иначе «Нужно») верно по требованию «Порционное получение группы связей намерения». Через openspec-update-change добавить в tasks.md в конец Phase 3, после всех существующих задач, новую задачу 3.17 (следующий свободный номер 3.N, если 3.17 занят) — первой из новых задач фазы 3, до задачи по F2. Суть: в test/app/long_term_relation_app_flow_test.dart три теста — «архивирование снимает отметку, восстановление обновляет выдачу и причину» и два «вложенная связь сохраняется при добавлении оставшихся отметок / при сбросе первоначальных отметок» — явно выбирают нужную группу вкладки «Связи» через интерфейс (а не полагаются на группу по умолчанию) и проверяют прежние сценарии без ослабления утверждений. Критерии приёмки: три теста проходят и проверяют те же сценарии; `mise run check` завершается успешно целиком, включая `check:process-tests`, что восстанавливает условие «Ready to advance» фазы 3, ложно отмеченное в 3.16. Проверка: `mise exec --no-deps -- flutter test test/app/long_term_relation_app_flow_test.dart`, затем `mise run check`. Зависимости: 3.13. Предполагаемые файлы: test/app/long_term_relation_app_flow_test.dart. Отметку 3.16 и другие завершённые задачи не менять; plan.md не менять. Код в lib/ не менять.

## F2 · Low — Выбранный при создании вид «Вспомогательное» теряется после снятия и повторной отметки

- **Решение:** Устранить
- **Как устранить:** Исправить код по действующей спецификации (требование «Создание намерения из поиска участника» в specs/long-term-relation-management/spec.md не меняется). Через openspec-update-change добавить в tasks.md в конец Phase 3, после всех существующих задач (в том числе после задачи по F1), новую задачу со следующим свободным номером 3.N (ожидается 3.18). Суть: в lib/src/long_term_relation/presentation/batch_picker/relation_batch_view_model.dart поиск участника помнит вид, выбранный в панели создания для созданного в этом поиске намерения, на всю сессию поиска независимо от снятия отметки; при повторной отметке через toggle и любом подтверждённом добавлении связи с этим намерением в группах «Нужно» и «Можно использовать» оно становится вспомогательным в той же операции (OutgoingRelationCandidate.becomesSupporting). Если связь с ним не создана — отметка снята и не возвращена, поиск закрыт или сброшен, добавление отклонено — намерение остаётся главным. Обычные (не созданные в поиске) намерения вид не получают. Обновить комментарий к acceptCreated, который сейчас говорит «пока она стоит». Критерии приёмки: сценарий «создать с видом по умолчанию → снять отметку → отметить снова → добавить» делает намерение вспомогательным и закреплён тестом; существующий тест «снятая отметка оставляет созданное намерение главным» продолжает проходить. Проверка: `mise exec --no-deps -- flutter test test/long_term_relation/presentation/batch_picker` (только тесты изменённого модуля и прямых потребителей, без полного `mise run check` — полные проверки фазы выполняет задача по F1 и следующее ревью реализации). Зависимости: 3.9 и задача по F1. Предполагаемые файлы: relation_batch_view_model.dart и test/long_term_relation/presentation/batch_picker/relation_batch_view_model_test.dart. Завершённые задачи и plan.md не менять.
