## Findings

### F8 · Medium — Критерий завершения 3.1 требует результат последующей задачи 3.3

- **Evidence:** В [tasks.md](tasks.md), задача 3.1, третий критерий приёмки (строка 779), требует: «одну функцию используют реальный и тестовые адаптеры». Однако подключение `MoveFavoriteIntention` к `DriftPersonalGraphRepository.execute`, применение этой функции в транзакции и проверка контракта на реальном адаптере запланированы только в 3.3 (строки 797–806). Задача 3.3 зависит от 3.1 и 3.2, а 3.2 — от 3.1. На baseline `lib/src/graph/data/drift_personal_graph_repository.dart:523` не обрабатывает команду перестановки; существующие части избранного реализуют только отметки и чтение списка. Следовательно, требование о реальном потребителе не удовлетворено предыдущими фазами. Схема `intent-driven` разрешает отмечать задачу только после выполнения всего её контракта; оркестратор исполняет незавершённые задачи по одной, строго в порядке файла.
- **Impact:** Чтобы закрыть 3.1 буквально, исполнителю придётся заранее выполнить подключение реального адаптера из 3.3, до появления диагностики из 3.2. Альтернатива — отметить 3.1 выполненной при невыполненном критерии. Обе возможности нарушают заданную последовательность и делают границу проверяемого результата первой задачи неоднозначной, хотя формальный список зависимостей ацикличен.
- **Required change:** Разделить критерии невыполненных задач фазы 3 так, чтобы 3.1 завершалась проверенным контрактом и чистой функцией без требования уже подключённого реального адаптера, а обязательное использование этой же функции реальным адаптером и его проверка оставались критериями 3.3 и контрольной точки 3.4. Сохранить общую функцию по решению 9 design и ADR-0015. Каждый критерий должен проверяться к завершению своей задачи при порядке 3.1 → 3.2 → 3.3 → 3.4; выполненные задачи фаз 1–2 менять не требуется.
