## F3 · Low — Параметр `chosen` у `PriorityPicker.itemLabel` не нужен ни одному потребителю

- **Решение:** Устранить
- **Как устранить:** Решение пользователя: убрать параметр. Новой задачей в конце фазы 2 (следующий свободный номер 2.x, после всех существующих задач) изменить контракт PriorityPicker.itemLabel на String Function(DoablePriority priority), так что доступное название пилюли зависит только от приоритета, а выбор объявляется диктору один раз через selected. Обновить вызов и _Pill-данные в priority_picker.dart, потребителя в relation_details_sheet.dart (убрать отбрасываемый параметр) и тестовый образец _itemLabel в test/design_system/priority_picker_test.dart: убрать «, выбран», при этом проверка isSelected у пилюли остаётся. Поведение продукта не меняется: рабочий потребитель параметр уже игнорирует. Спецификации и design не меняются; правка F1 в relation_details_sheet.dart затрагивает другое место файла, порядок с ней не важен. Меняются tasks.md и три названных файла.

## F4 · Low — Политика предъявления связи выражена флагом рядом с существующим закрытым типом

- **Решение:** Устранить
- **Как устранить:** Решение пользователя: выполнить в фазе 3, в фазе 2 задачу не добавлять и четвёртый вариант _PresentationPolicy не вводить. Причина: acceptRelationRestoreFromCreation объявляет успех через оболочку и сразу отдаёт ей отказ, этому не соответствует ни один из трёх вариантов, а фаза 3 удаляет этот поток. Сейчас изменить только раздел фазы 3 в plan.md (Boundaries и при необходимости Ready to advance): вместе с удалением восстановления из поиска _acceptRelation в graph_command_coordinator.dart принимает один параметр _PresentationPolicy вместо флагов announcesSuccess и initiatorReleased; создание, удаление и добавление пачки идут по standard, изменение, архивирование и восстановление по silentSuccess; ветка успеха без сообщения описана в одном месте. В tasks.md фазу 3 не добавлять: её задачи планирует оркестратор из plan.md, номера фаз не менять. Поведение продукта не меняется: те же тесты координатора должны проходить. Код в рамках этого решения сейчас не меняется.
