## Direction

Перевести CI от неявного расширения toolchain во время рабочих команд к явной
модели, где setup каждого job полностью определяет доступный ему набор
инструментов. Изменение проводится одним согласованным контуром: сначала
контрактные проверки фиксируют требуемую границу, затем workflow начинает
соблюдать её, а итоговые логи подтверждают отсутствие поздних установок.

## Plan Constraints

Точные версии инструментов, разделение jobs, стандартные cache keys и безопасная
область видимости GitHub cache сохраняются. Расширение на Pub, Gradle, Flutter
first-use caches или trusted cache warming не входит в этот план.

## Phase 1: CI toolchain ограничен setup-контрактом каждого job

**Objective:**
Заменить автоматическую материализацию полного набора проекта на явное
использование частичных toolchain, установленных и закэшированных setup-шагами.

**Outcome:**
Project и Android jobs используют только Flutter/Dart, OpenSpec job использует
только Node.js/OpenSpec, а рабочие команды не могут незаметно расширить эти
наборы. Репозиторный CI contract test защищает границу от регрессии.

**Boundaries:**
Фаза охватывает политику auto-install, способы запуска существующих проверок,
явную cache-конфигурацию и regression evidence. Она не меняет прикладное
поведение, версии инструментов или общую стратегию прогрева зависимостей.

**Ready to advance:**
Статический CI-контракт и полный репозиторный gate успешны, OpenSpec change
валиден, а pull-request логи не содержат установки необъявленных инструментов
после setup.
