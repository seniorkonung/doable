## Why

Частичные установки инструментов в CI теряют смысл, потому что последующие
вызовы `mise exec` и `mise run` автоматически устанавливают весь недостающий
набор из корневого `mise.toml`. В результате короткая OpenSpec-проверка тратит
почти всё время на неиспользуемый Flutter, а поздно установленные инструменты не
попадают в уже сохранённый кэш `mise-action`.

## What Changes

- Закрепить setup-шаг `mise-action` как единственного владельца установки
  инструментов внутри каждого CI job.
- Запретить автоматическую установку недостающих инструментов после setup и
  запускать mise-задачи без подготовки полного toolchain.
- Запускать OpenSpec напрямую из PATH, экспортированного `mise-action` после
  установки Node.js и OpenSpec.
- Явно сохранить действующее кэширование каждой частичной установки и добавить
  regression-проверки CI-контракта.

## Capabilities

### New Capabilities

- `ci-toolchain-provisioning`: Изолированная установка и повторное использование
  только необходимого конкретному CI job набора инструментов.

### Modified Capabilities

Нет.

## Impact

Изменение затрагивает GitHub Actions workflow и его focused shell-тест. Публичные
API, приложение, версии инструментов, стандартные ключи `mise-action` и продуктовые
спецификации не меняются. Прогрев кэшей ветки `main`, Pub/Gradle cache и Flutter
first-use cache остаются вне текущего изменения.
