# Манифест проверки ADR

- Status: completed
- Review date: 2026-09-29

## Результат проверки

Проверка архитектурных решений изменения `show-and-filter-intention-tags` завершена. [Design](design.md) согласован с применимыми принятыми ADR: общий поиск расширяет существующую границу личного графа, получает ограниченные порции намерений с полными собственными тегами и согласовывает подтверждённые изменения по общей ревизии.

Новый ADR не создан. Решения design проверены по трём критериям: долговременное архитектурное обязательство, влияние на будущие изменения и отсутствие покрытия применимым ADR либо намеренный пересмотр такого ADR.

- Общий поиск в четырёх контекстах, типизированные параметры, составные чтения и расширение подтверждённых пакетов применяют ADR-0009. Согласование недостающих совпадений после удаления исключённого тега сохраняет ограниченные чтения, принятую ревизию и атомарное предъявление результата; отдельный владелец данных, долговечная ревизия или бессрочный журнал изменений не появляются.
- Полный состав тегов каждой сводки следует ADR-0013. Пакетное получение назначений только намерениям текущей порции не меняет полноту списка одного получателя и не превращает весь каталог намерений в неограниченный снимок.
- Условия по `TagId` и исключение второго участника по `IntentionId` применяют ADR-0003. Сохранение условия после удаления тега, совместная логика «И» и немедленное применение относятся к поведению поиска, закреплённому спецификациями.
- SQL-предикат, временные отношения параметров, пакетное получение тегов, состав идентичности курсора и подключение предъявления тегов только в поисках — решения реализации данной возможности. Они остаются внутри существующих контрактов ADR-0002, ADR-0009 и ADR-0013 и не вводят нового долговечного контракта схемы.

Существенных неразрешённых архитектурных решений, требующих пересмотра design, не выявлено. Будущие требования к интерфейсу остаются отдельным входом для соответствующих задач. Перед объединением необходимо сверить результат параллельного PR по удалению тегов у долговременных связей; этот манифест не подтверждает совместимость с ещё не включёнными в рабочее дерево изменениями.

Предметный язык проверен по [CONTEXT.md](../../../CONTEXT.md): намерение, действие, готовность к действию, дневной выбор, исходное намерение, путь выбора, долговременная связь и тег используются в установленных значениях. Обязательные и исключённые теги обозначают условия конкретного поиска, а не новые разновидности тега. Назначения намерениям составляют область этого поиска; более широкий круг получателей в текущем словаре согласуется с параллельным PR при объединении.

## Ключевые ADR для этого изменения

- [ADR-0009 — Объединить управление личным графом и согласование его снимков](../../../docs/adr/0009-unify-personal-graph-module-and-revision.md) — `accepted`; действующее ограничение единой границы `PersonalGraphRepository`, последовательного исполнения, общей ревизии, согласованных порций и применения подтверждённых пакетов ровно один раз. Расширение снимков и чтение недостающей части выдачи продолжают этот контракт.
- [ADR-0013 — Читать списки тегов полными согласованными снимками](../../../docs/adr/0013-load-complete-tag-snapshots.md) — `accepted`; требует полного проверенного состава назначений одного получателя без искусственного предела и на одной ревизии. Ограничение относится к порции найденных намерений, а не к числу их тегов.
- [ADR-0003 — Использовать отдельные типы UUID-идентификаторов предметных сущностей](../../../docs/adr/0003-use-typed-uuid-identifiers-for-domain-entities.md) — `accepted`; условия используют устойчивый `TagId`, результаты и исключение участника — `IntentionId`. Переименование и одинаковые названия не подменяют идентичность.
- [ADR-0002 — Хранить локальный граф в SQLite через Drift](../../../docs/adr/0002-use-drift-sqlite-for-local-graph.md) — `accepted`; задаёт транзакции и допустимые границы физических соединений. Временные отношения запроса и пакетные чтения выполняются существующим адаптером через эти границы.

## Дополнительный контекст

- [ADR-0006 — Считать timestamps с часов устройства наблюдениями, а не причинным порядком](../../../docs/adr/0006-treat-device-clock-timestamps-as-observations.md) — `accepted`; порядок подтверждённых изменений определяется ревизией. Согласование тегов не использует временные метки намерения как версию и не продвигает их ради обновления выдачи.
- [ADR-0007 — Ограничить пользовательский текст графа корректным Unicode без NUL](../../../docs/adr/0007-restrict-graph-user-text-to-unicode-without-nul.md) — `accepted`; сохраняет проверку поискового текста до преобразований и проверку прочитанных названий тегов перед построением успешных моделей.
- [ADR-0008 — Считать SQLite schema-functions долговечным контрактом](../../../docs/adr/0008-treat-sqlite-schema-functions-as-durable-contract.md) — `accepted`; сохраняет обязательства существующих функций поиска и тегов на каждом физическом соединении. Временные отношения параметров не изменяют сохраняемую схему или семантику её функций.
- [ADR-0011 — Вычислять счётчики связей из согласованных снимков графа](../../../docs/adr/0011-derive-relation-counts-from-graph-snapshots.md) — `accepted`; расширение сводок тегами сохраняет пакетное получение существующих счётчиков. Фильтр намерений не ограничивает соседство при их вычислении. Количество совпадений поиска остаётся отдельным агрегатом своего предиката.
- [ADR-0005 — Читать каталог намерений ограниченными снимками](../../../docs/adr/0005-use-bounded-catalog-snapshots.md) и [ADR-0001 — Сосредоточить управление намерениями в глубоком модуле](../../../docs/adr/0001-deep-intention-management-module.md) — в документах `accepted`; исторический контекст в заменённой области. Проверена цепочка ADR-0001 → ADR-0005 → ADR-0009. Действующую общую границу и протокол согласования определяет ADR-0009.

В текущем рабочем дереве применимых предложенных ADR других активных изменений не обнаружено. Решения из параллельного PR остаются контекстом для последующей сверки после получения его изменений.

## ADR, принадлежащие этому изменению

Нет. Изменение `show-and-filter-intention-tags` не создаёт собственных ADR; целей их принятия при архивации нет. Наибольший существующий номер в `docs/adr/` — ADR-0013.

Ссылки на применимые решения не меняют их принадлежность или статус. Принятые ADR остаются неизменными; ADR активного изменения, если появятся при дальнейшем пересмотре, должны оставаться `proposed` и редактируемыми до архивации. Статус `completed` этого манифеста означает завершение проверки и согласование с design, а не принятие нового ADR или готовность реализации.
