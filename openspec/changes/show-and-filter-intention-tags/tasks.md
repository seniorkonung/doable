# Задачи первой фазы

Пакет относится к первой фазе [плана](plan.md). Поведение определяют [спецификации намерений](specs/intention-management/spec.md), [дневных выборов](specs/daily-choice-management/spec.md) и [участников связей](specs/long-term-relation-management/spec.md); подход и архитектурные ограничения — [design](design.md) и [манифест ADR](adr.md).

Задачи охватывают общий контракт поиска и его выполнение. Автоматическое согласование изменений тегов относится ко второй фазе, а конкретный интерфейс и подключение предъявления тегов — к третьей. При реализации учитывается доступный результат параллельного PR; этот пакет не изменяет миграции удаления тегов у связей и не зависит от сохранения таких назначений.

Каждый инкремент включает проверки нового поведения с подтверждённым провалом до реализации и успехом после неё. После изменений Dart применяются правила репозитория для проверки запущенного приложения либо CLI. Пути ниже обозначают ожидаемые места изменений; новый тестовый файл отмечен отдельно.

- [x] 1.1 Условия наличия и отсутствия тегов представлены одним неизменяемым типизированным значением

- [x] 1.5 Совместный запрос отбирает допустимые намерения по названию и обоим наборам тегов до подсчёта и ограничения порции

    - Удалённый обязательный идентификатор успешно даёт ноль совпадений, исключённый больше никого не отсекает; число тегов не ограничивается размером порции или числом параметров одного SQL-выражения. Поиск не изменяет граф и временные метки.

  - **Критерии приёмки:**
    - Выполнено требование «Совместный поиск сохраняет продолжение навигации по тегу» из [спецификации намерений](specs/intention-management/spec.md) по решению 3 [design](design.md): на настоящем `DriftPersonalGraphRepository` цепочка `getTaggedEntitiesPage` → `getCatalogPage` → продолжение исходной навигации сохраняет курсор, ревизию и предметные данные.
