## Context

Приложение не задаёт тему. Оба `MaterialApp` строятся без `theme`: и `_BootstrapStatusApp` с состоянием загрузки и отказами подготовки локального хранилища, и корневой `MaterialApp.router`. Поэтому экраны рисуются стандартной темой Material 3.

Экраны собраны из виджетов Material:
- кнопки: `FilledButton` — около 50, `TextButton` — около 35, `OutlinedButton` — 28, `IconButton` — 26;
- `AppBar` — 20, `TextField` — 18, `CircularProgressIndicator` — 17;
- `Card`, диалоги, `ListTile`, `ChoiceChip`, две модальные нижние панели;
- сообщения общей поверхности через `SnackBar` в `GraphOperationPresenter`.

Свои цвета экраны берут из ролей темы:
- `error` и `onError` — опасные кнопки и текст ошибок;
- `primary` и `onPrimary` — выбранный день календаря, отметки дней и включённая готовность к действию;
- `secondaryContainer` — индикатор выбранного пункта и подложка кнопки быстрого создания;
- `surfaceContainer` — фон панели навигации;
- `onSurfaceVariant`, `surface`, `outline`, `scrim`.

Стили текста — `titleMedium`, `labelLarge`, `titleSmall`, `titleLarge`, `headlineSmall` и `bodySmall`. Явных цветов в коде нет.

Источник значений — приватные материалы дизайна в папке `context/`, исключённой из git. В `tokens.json` лежат:
- цвета светлой и тёмной тем;
- 14 стилей текста на Inter;
- шкалы отступов и радиусов, размеры элементов, тени.

Раздел дизайн-системы о переносе во Flutter предписывает `DoableColors` как расширение темы и `DoableType` для стилей текста. Где его советы расходятся с ADR или текущей версией Flutter, действуют решения проекта.

Макеты подключают Inter с осями `wght` (400–700) и `opsz` (14–32). Браузер сам выставляет оптический размер по кеглю в CSS-пикселях.

Ограничения:
- Release-сборка не имеет разрешения на сеть ([ADR-0004](../../../docs/adr/0004-keep-personal-graph-device-local.md)).
- Существующие требования обязывают различать состояния не только цветом.
- Во Flutter 3.47.1 `FontWeight` сам выставляет ось `wght` вариативного шрифта. Явная `FontVariation('wght')` её перекрывает.
- На Android окно запуска в ночном режиме уже тёмное, а `uiMode` входит в `configChanges` активности.
- Минимальная версия Android — 7.0, системная тёмная тема в ней не предусмотрена.

Параллельное изменение `add-contribution-statistics` пересекается с этим изменением только в индексе `docs/adr/README.md`: оба добавляют в него строки ADR. Остальные его файлы другие, а его экраны получат тему после слияния обеих веток.

## Goals / Non-Goals

**Goals:**
- Перенести токены дизайн-системы в типизированный код.
- Построить из токенов светлую и тёмную темы и применить их к обоим `MaterialApp` по требованию «Светлое и тёмное оформление по системной настройке».
- Поставлять Inter вместе с приложением. Стили текста должны повторять макеты по весу, оптическому размеру и межстрочному интервалу (требование «Шрифт интерфейса»).
- Оформить по дизайн-системе виджеты Material, которые приложение уже использует.
- Показывать компоненты Widgetbook в настоящих темах и дать раздел основ.

**Non-Goals:**
- Компоненты дизайн-системы (панель навигации, верхняя панель, нижние панели, строки списков), раскладка экранов по макетам, изменения поведения.
- Совпадение существующих экранов с макетами: их раскладка остаётся раскладкой Material.
- Требование к контрасту. По решению владельца продукта его нет в спецификации, пары цветов проверяет сама дизайн-система.
- Генератор токенов и автоматическая сверка с `tokens.json`.
- Иконки сверх Material Icons, иконка приложения и заставка запуска, настройка темы в приложении, кольцо фокуса клавиатуры из дизайн-системы.
- Тени дизайн-системы как токены. Material рисует тени по высоте подъёма, а собственные списки теней понадобятся первому собственному плавающему компоненту.

## Decisions

Решения 1–7 закреплены в [ADR-0029](../../../docs/adr/0029-represent-design-system-as-foundation-module.md). Решения 8 и 9 относятся только к этому изменению.

### 1. Выделить основы оформления в отдельный модуль

Новый модуль `lib/src/design_system/` — единственное место, которое знает значения токенов и строит из них темы. Будущие компоненты дизайн-системы появятся в нём же.

Упрощённая C4-схема показывает компоненты внутри Flutter-приложения. `Bootstrap app` — `_BootstrapStatusApp`, `Root app` — корневой `MaterialApp.router`, `Feature screens` — существующие страницы, `Design foundation` — новый модуль. `Inter asset` — файл шрифта с лицензией, `Design reference` — приватные материалы в `context/`.

```text
+------------------+          +------------------------------+
| Widgetbook       |          | Design reference             |
| (Flutter, Linux) |          | context/, not in git         |
+------------------+          +------------------------------+
         |                                   :
         | uses themes                       : values copied
         | (package:doable)                  : by hand
+--------|-----------------------------------:---------------+
|        v                                   v               |
|  +--------------------------------------------------+      |
|  | Design foundation                                |      |
|  | tokens, DoableColors, typography, theme builder  |      |
|  +--------------------------------------------------+      |
|        ^              ^              ^           |         |
|        | themes       | themes       | reads     | font    |
|        |              |              |           v         |
|  +-----------+  +-----------+  +-----------+  +--------+   |
|  | Bootstrap |  | Root      |  | Feature   |  | Inter  |   |
|  | app       |  | app       |  | screens   |  | asset  |   |
|  +-----------+  +-----------+  +-----------+  +--------+   |
|                                                            |
| Doable app (Flutter, Android)                              |
+------------------------------------------------------------+
```

- Оба `MaterialApp` получают из модуля светлую и тёмную темы.
- Существующие экраны модуль не импортируют: они читают роли через `Theme.of(context)`.
- Будущие компоненты будут читать `DoableColors` и `DoableType` напрямую.
- Widgetbook собирает тот же модуль через зависимость от пакета приложения.
- Значения переносятся из приватных материалов вручную: это не зависимость сборки и не зависимость времени выполнения.

Альтернативы:
- Тема внутри `lib/src/app/` связала бы будущие общие компоненты со сборкой приложения.
- `lib/src/shared/presentation/` смешал бы дизайн-систему с несвязанной инфраструктурой представления.

### 2. Переносить токены в код вручную

Имена в коде повторяют имена токенов в camelCase, как предписывает дизайн-система.

- **Цвета** — расширение темы `DoableColors` с экземплярами для светлой и тёмной тем. Алиасы дизайн-системы — вычисляемые свойства, а не отдельные значения, поэтому разойтись с основой они не могут: `p1` и `danger` — это `accent`, `danger-soft` — `accent-soft`, `on-danger` — `on-accent`.
- **Стили текста** — `DoableType`, 14 стилей без цвета. Цвет задают тема и место использования.
- **Шкалы отступов и радиусов** — константы.
- **Полнота по построению.** Набор цветовых токенов и набор стилей перечислены по одному разу, и компилятор требует значение каждого токена в обеих темах, например через перечисление с исчерпывающим сопоставлением. Поэтому `copyWith`, `lerp` и страницы Widgetbook не могут пропустить токен.

Переносятся полностью:
- палитра и шкала стилей текста — по решению владельца продукта фундамент сразу определяет все основы дизайна. Тема берёт из них роли, а цвета без роли Material (цвета тегов, `p2`–`p4`, `track`, `bg-fade`) до появления своих компонентов видны на странице «Цвета» Widgetbook;
- шкалы отступов и радиусов — темы компонентов используют большую часть шагов, а неполная шкала подталкивала бы к числовым литералам.

Из размеров переносится только `control-height`: темы кнопок берут его как минимальную высоту. Размеры конкретных компонентов (высота панели навигации, размер отметки выбора, толщины линий связей) и списки теней появятся вместе с компонентом, которому они нужны.

Расширение темы, а не статические константы, выбрано для цветов потому, что:
- цвет зависит от темы;
- при смене темы `ThemeExtension.lerp` плавно переводит цвета;
- Widgetbook переключает темы своим дополнением.

Альтернатива — генератор из `tokens.json`. Отвергнута:
- материалы дизайна приватны и недоступны в CI;
- локальный генератор с закоммиченным результатом — лишний инструмент ради примерно 60 редко меняющихся значений;
- автоматическая сверка в CI невозможна по той же причине.

Повторный экспорт сверяется вручную со значениями модуля: значения нового `tokens.json` сравниваются по именам токенов с константами модуля, а расхождения переносятся в модуль. Этот порядок записан в README приватных материалов.

### 3. Строить роли Material из токенов, `primary` — это `ink`

| Роль `ColorScheme` | Токен |
|---|---|
| `primary` / `onPrimary` | `ink` / `bg` |
| `primaryContainer` / `onPrimaryContainer` | `fill` / `ink` |
| `secondary` / `onSecondary` | `ink` / `bg` |
| `secondaryContainer` / `onSecondaryContainer` | `fill` / `ink` |
| `tertiary` / `onTertiary` | `accent` / `on-accent` |
| `tertiaryContainer` / `onTertiaryContainer` | `accent-soft` / `accent` |
| `error` / `onError` | `danger` / `on-danger` |
| `errorContainer` / `onErrorContainer` | `danger-soft` / `danger` |
| `surface`, `surfaceDim`, `surfaceBright`, `surfaceContainerLowest` | `bg` |
| `surfaceContainerLow`, `surfaceContainer`, `surfaceContainerHigh` | `raised` |
| `surfaceContainerHighest` | `fill` |
| `onSurface` / `onSurfaceVariant` | `ink` / `muted` |
| `outline`, `outlineVariant` | `hairline` |
| `inverseSurface` / `onInverseSurface` / `inversePrimary` | `ink` / `bg` / `accent` |
| `scrim` | `scrim` |
| `surfaceTint` | прозрачный: тонального подъёма Material 3 нет |

Почему так:
- В дизайн-системе основная кнопка — `ink` с текстом `bg`, а `FilledButton` берёт `primary`.
- Тихая кнопка (`fill` с текстом `ink`) совпадает с `FilledButton.tonal` через `secondaryContainer`.
- Нижние панели и диалоги Material 3 берут фоны `surfaceContainerLow` и `surfaceContainerHigh`, и становятся `raised`.
- Панель навигации получает фон `raised` и индикатор `fill`, как требует дизайн-система.
- Кнопка быстрого создания сохраняет собственную подложку `fill`, которую требует `quick-creation`.

Альтернатива — `primary` = `accent`. Тогда выбранные состояния в существующих виджетах стали бы ближе к дизайну. Но пришлось бы переопределять `FilledButton`, а это задевает и `FilledButton.tonal`, и индикаторы загрузки.

Принятые следствия на время перехода:
- выбранный день календаря, отметки дней, включённая готовность к действию, флажки и включённые переключатели становятся `ink`, а не акцентными; они переходят на дизайн вместе со своими экранами;
- в светлой теме панель навигации сливается со страницей: `raised` и `bg` там совпадают, а линии сверху у существующей панели нет. По решению владельца продукта это принимается до перевода панели на дизайн.

### 4. Оформлять только используемые виджеты Material

| Виджет | Оформление |
|---|---|
| `FilledButton` | Пилюля минимальной высоты `control-height`, отступы по бокам `space-4`, подпись `section`. Неактивная: `fill` с подписью `grip` |
| `TextButton` | Подпись `accent`. Неактивная — `grip` |
| `OutlinedButton` | Тихая кнопка дизайн-системы: плоскость `fill` без обводки, подпись `ink`, значок `muted` |
| `Card` | `fill` без тени, углы `radius-lg` |
| `AppBar` | Фон `bg` без смены цвета и тени при прокрутке, заголовок по центру, активные значки `ink`, включая ведущую кнопку и действия. Высота остаётся стандартной |
| Диалоги | Заголовок в стиле `title`, затемнение `scrim`, боковой отступ `space-8` |
| Модальные нижние панели | Затемнение `scrim`, ручка `grip` 36×4. Тема затрагивает панели, открытые через `showModalBottomSheet`, то есть меню режимов быстрого создания |
| `Switch` | Выключенный: ползунок и обводка дорожки `muted`, дорожка `fill`. Включённый следует ролям решения 3: дорожка `ink`, ползунок `bg` |
| `SnackBar` | Плавающий, плоскость `ink` с углами `radius-lg`, текст в стиле `row`. Отступы `space-5` по бокам и `space-3` снизу |
| Поле ввода | Заполненное `fill` без рамок в любом состоянии, углы `radius-sm`, внутренние отступы стандартные |
| Индикаторы загрузки | Дуга `muted` на дорожке `hairline`, толщина линии 2 |
| `ChoiceChip` | Форма пилюли |

- **Обычные значки.** `ThemeData.iconTheme` явно задаёт `ink` и размер 24 для `Icon` без собственного цвета, размера или локальной темы. Одного `ColorScheme.onSurface` недостаточно: конструктор [ThemeData](https://api.flutter.dev/flutter/material/ThemeData/ThemeData.html) использует для стандартной темы значков отдельные цвета Material.
- **Кнопки со значком.** `ThemeData.iconButtonTheme` явно задаёт `muted` обычным активным невыбранным `IconButton`. Настройка цвета учитывает состояние: выключенные и выбранные кнопки сохраняют стандартные правила Material 3 через роли решения 3, в том числе `onSurface` с непрозрачностью 38 % для выключенного значка. Постоянный `muted` для всех состояний не задаётся. В Material 3 [IconButtonTheme имеет приоритет над IconTheme](https://api.flutter.dev/flutter/material/IconButton-class.html), поэтому общая тема значков не перекрашивает активные невыбранные кнопки в `ink`.
- **Выключенные кнопки внутри строк.** Во Flutter 3.47.1 `ListTile` заменяет `foregroundColor` вложенной темы кнопок постоянным цветом строки. Поэтому тема основ дополнительно задаёт `ButtonStyle.iconColor` только для `WidgetState.disabled`: `ink` с непрозрачностью 38 %, как стандартный `onSurface` Material 3. Остальные состояния возвращают `null` и сохраняют приоритеты строки, `AppBar` и явных параметров виджета.
- **Значки верхней панели.** `AppBarTheme` задаёт `ink` через `iconTheme` и `actionsIconTheme`. Локальное оформление кнопок `AppBar`, включая ведущую кнопку и действия, должно перекрывать общий `muted` для активных значков, сохраняя стандартное оформление выключенных состояний.
- **Значения по умолчанию.** `ListTile`, флажки и подсказки остаются в оформлении Material по умолчанию и следуют ролям из решения 3. Локальные темы значков внутри компонентов сохраняются.
- **Выключенный переключатель.** Material 3 рисует его ползунок и обводку цветом `outline`, то есть декоративным `hairline` по дорожке `fill`, и выключенное состояние почти исчезает. Поэтому тема рисует их цветом `muted`, как активные невыбранные кнопки со значком.
- **Явные параметры виджетов.** Цвета, которые экраны задают сами, например опасные кнопки через `error` и `onError`, по-прежнему побеждают тему.
- **Локальные цвета экранов.** Цветовые константы, которые экраны задают сами, в этом изменении не меняются. Например, панель создания намерения рисует собственные затемнение и ручку 32×4, поэтому до перевода на дизайн она выглядит иначе, чем меню режимов.
- **Индикаторы загрузки.** Дизайн-система рисует загрузку дугой `muted` на `hairline` и не тратит на неё акцент.
- **Поля ввода.** Сейчас у них подписи `labelText`. Стандартные отступы Material оставлены, чтобы плавающие подписи помещались; точную геометрию полей задаст компонент дизайн-системы.

Альтернативы:
- Оформить все виджеты Material — это работа впрок.
- Заменить виджеты в экранах — это изменение раскладки, которое отнесено к экранам.

### 5. Применять обе темы в обоих `MaterialApp` и следовать системе

`_ReadyApp` и `_BootstrapStatusApp` получают `theme`, `darkTheme` и `ThemeMode.system` из одной функции модуля. Так требование покрывает и состояние загрузки, и отказы подготовки хранилища.

Состояния приложения для темы нет: спецификация оставляет выбор только системе. На устройстве без системной настройки Flutter сообщает светлую яркость.

Нативную часть Android менять не нужно:
- окно запуска в ночном режиме уже тёмное: ночной `LaunchTheme` и `?android:colorBackground`;
- активность не пересоздаётся при смене `uiMode`, поэтому страницы, панели и введённый текст переживают смену темы.

`MaterialApp` переводит тему плавно, `DoableColors` участвует в этом через `lerp`.

### 6. Подключить Inter как вариативный шрифт и повторить оптический размер макетов

**Файл шрифта.** Вариативный файл прямого начертания из официального выпуска Inter с осями `wght` и `opsz` лежит внутри модуля основ оформления вместе с лицензией SIL Open Font License 1.1. Файлы под `lib/` пакета доступны Widgetbook по пути `packages/doable/…` (решение 8). Версия фиксируется при добавлении, контрольная сумма — рядом с файлом. Семейство `Inter` объявлено в `pubspec.yaml` приложения и задано теме как `fontFamily`, поэтому его получает весь текст Material.

**Вес** задаётся только через `FontWeight`. Стили токенов используют веса от 400 до 700, а вес 650 задают компоненты тем же способом. Во Flutter 3.47.1 `FontWeight` сам выставляет ось `wght`. Явная `FontVariation('wght')` перекрыла бы вес и сломала бы `copyWith(fontWeight: …)`, которым календарь выделяет сегодняшний день. Совет дизайн-системы задавать 650 через `fontVariations` для этой версии Flutter устарел.

**Оптический размер.** В макетах браузер ставит `opsz`, равный кеглю в CSS-пикселях. Flutter эту ось сам не выставляет: из `fontWeight` движок задаёт только `wght`, остальные оси — лишь явно. Без явного значения весь текст рисовался бы оптическим размером шрифта по умолчанию. Поэтому каждый стиль `DoableType` задаёт `FontVariation.opticalSize`, равный своему кеглю в логических пикселях; шрифт сам ограничивает значение диапазоном 14–32.

**Межстрочный интервал.**
- `height` — отношение высоты строки к кеглю;
- `TextLeadingDistribution.even` повторяет поровну распределённый интервал CSS;
- межбуквенный интервал из `em` переводится в логические пиксели.

**Запасные шрифты.** `fontFamilyFallback` не задаётся. Символы вне набора Inter движок берёт из шрифтов устройства.

**Лицензия** лежит рядом со шрифтом и объявлена в списке `flutter: licenses:` в `pubspec.yaml`. Сборка включает её в сведения о лицензиях (NOTICES), которые читает экран лицензий Flutter, и завершается ошибкой, если файла нет. Отдельный ассет, тест и регистрация в `LicenseRegistry` не нужны.

### 7. Считать размеры из дизайна минимальными

- **Минимальные размеры.** Темы задают минимальные размеры, например минимальную высоту кнопок, но не фиксированные.
- **Высота `AppBar`.** Она остаётся стандартной до перевода верхней панели на дизайн-систему.

### 8. Показывать основы в Widgetbook

- **Темы.** Дополнение темы Widgetbook получает светлую и тёмную темы приложения вместо `ThemeData()`, поэтому все примеры рисуются в настоящем оформлении.
- **Раздел «Основы».** Новый раздел содержит примеры «Цвета» и «Типографика»: каждый цвет `DoableColors` с именем токена и каждый стиль `DoableType` с образцом текста, в выбранной теме. Примеры строятся из модуля и значений не дублируют.
- **Шрифт в каталоге.** Widgetbook — отдельное приложение. Шрифты пакета-зависимости Flutter регистрирует под именем `packages/doable/Inter`, а стили `DoableType` ссылаются на `Inter`. Поэтому Widgetbook объявляет в своём `pubspec.yaml` семейство `Inter` с тем же файлом через путь `packages/doable/…`, без копии файла.
- **Проверка шрифта.** Widgetbook на Linux рисует настоящим Inter, в отличие от тестового шрифта `flutter_test`, поэтому подходит для сверки раздела «Основы» с макетами. Экранов приложения в каталоге нет, их проверяют на устройстве (решение 9).
- **Проверка значков.** В первой фазе в обеих темах вручную проверяется локальная композиция с обычным `Icon`, обычным активным невыбранным и выключенным `IconButton`, ведущей кнопкой и активным и выключенным действием `AppBar`. Она использует темы модуля через Widgetbook и подтверждает цвета и приоритеты решения 4 до подключения тем к приложению.

### 9. Проверять оформление вручную, без новых тестов

По решению владельца продукта тесты на оформление не пишутся: ни на токены, темы и шрифт, ни на сценарии `app-appearance`. Существующие тесты на тему приложения не переводятся и продолжают проходить с темой по умолчанию. Раскладка под новой темой проверяется вручную.

Ручная проверка идёт на Android-устройстве или эмуляторе, в обеих темах:
- **Запуск при тёмной системной настройке** — при тёмной теме устройства состояние загрузки хранилища и начальная страница показаны в тёмном оформлении.
- **Смена настройки во время работы** — на странице намерения с начатым изменением названия в системных настройках включается тёмная тема. Открыта та же страница, введённый текст сохранён.
- **Интерфейс без доступа к сети** — в режиме полёта системные строки и названия намерений в каталоге набраны Inter.
- **Символы вне набора шрифта** — название намерения с эмодзи и иероглифами видно целиком в каталоге и на странице намерения.
- **Существующие экраны** — без обрезки и переполнения показаны:
  - каталог дневных выборов с календарём;
  - каталог и страница намерения;
  - панель создания намерения с открытой клавиатурой;
  - страницы связей и тегов;
  - диалоги удаления.
- **Выключенный переключатель выполнения** различим в обеих темах.
- **Значки и кнопки со значком** соответствуют решению 4: стрелки между шагами пути выбора — `ink`, обычные активные невыбранные кнопки в строках каталога тегов — `muted`, ведущая кнопка и активные действия `AppBar` — `ink`. Кнопки удаления тегов, временно выключенные при подтверждении или выполнении удаления, сохраняют стандартный цвет выключенного состояния Material 3 и различимы на фоне. Явные цвета виджетов и локальные темы компонентов сохраняются.

Внешний вид сверяется в обеих темах: раздел «Основы» в Widgetbook и главные экраны сравниваются с отрисованными состояниями макетов из `context/`.

## Risks / Trade-offs

- **[Риск] Цвета дизайна на раскладке Material местами выглядят неудачно.** Например:
  - тихая кнопка на карточке `fill` теряет видимую плоскость;
  - выбранный день календаря становится `ink`, а не акцентным;
  - в светлой теме панель навигации сливается со страницей;
  - панель создания намерения сохраняет собственные затемнение и ручку.

  → **Смягчение:** это принятые временные состояния до перевода экранов (решения 3 и 4); перед архивацией главные экраны просматриваются в обеих темах.
- **[Риск] Существующие тесты идут с темой Material по умолчанию и тестовым шрифтом.** Они не заметят, если размеры и отступы новой темы или настоящие переносы Inter нарушат раскладку. → **Смягчение:** ручная проверка главных экранов на устройстве и раздела «Основы» в Widgetbook (решение 9). Тестов на оформление нет по решению владельца продукта.
- **[Риск] Вес и оптический размер во Flutter могут отличаться от браузера.** → **Смягчение:** сравнить образцы `display`, `page-title` и `body` с отрисовкой макета и скорректировать подход при реализации.
- **[Риск] Токены отстанут от дизайна после повторного экспорта.** → **Смягчение:** при каждом экспорте значения нового `tokens.json` сверяются со значениями модуля, и константы обновляются. Автоматической сверки нет, потому что материалы приватны.
- **[Риск] Release APK вырастет на размер файла шрифта, около мегабайта.** Flutter не урезает текстовые шрифты. → **Смягчение:** принято.
- **[Риск] Параллельное `add-contribution-statistics` сливается с этим изменением.** → **Смягчение:** пересекается только индекс ADR. При любом порядке слияния в нём по одной строке ADR-0026–ADR-0029 в порядке номеров и абзацы обоих изменений. Ветка, которая сливается второй, разрешает конфликт индекса и проходит полную проверку, а экраны статистики получают тему автоматически.
- **[Риск] Обновления Flutter меняют значения Material по умолчанию.** → **Смягчение:** для используемых виджетов значения заданы явно, при обновлении Flutter — просмотр в Widgetbook.
- **[Риск] В тёмной теме могут проявиться неудачные сочетания, которых нет в дизайн-системе.** Пример — собственная прозрачность затемнения в панели создания намерения. → **Смягчение:** просмотр в тёмной теме перед архивацией.

## Migration Plan

Данные, схема хранилища и нативные ресурсы Android не меняются. Внешний вид меняется одним выпуском, откат — возврат изменения.
