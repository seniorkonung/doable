## Phase 1: Состояния дней доступны в календаре и согласуются с дневными выборами

- [ ] 1.1 Определить типизированные вход и результат ограниченного чтения состояний дней
  - **Критерии приёмки:**
    - `DailyChoiceDayStatusQuery` принимает включительный диапазон `CalendarDate`: первая дата не позже последней, длина не больше 14 недель.
    - Неизменяемый `DailyChoiceDayStatuses` содержит диапазон и состояния `DailyChoiceDayStatus { allCompleted, hasIncomplete }` только дней с выборами; отсутствие дня означает отсутствие выборов. Контракт результата — `GraphResult<GraphSnapshot<DailyChoiceDayStatuses>, DailyChoiceDayStatusesReadFailure>` с одним типом отказа.
    - Контракт описывает гарантии из решения 2 [дизайна](design.md) и [ADR-0024](../../../docs/adr/0024-derive-calendar-day-states-from-saved-daily-choices.md): все выборы даты, одна ревизия, отказ целого чтения вместо частичного результата; SQL остаётся внутри адаптера.
  - **Проверка:**
    - `mise exec --no-deps -- flutter test test/daily_choice/application/daily_choice_day_statuses_test.dart`: допустимые границы диапазона, отклонение обратного и слишком длинного диапазонов, неизменяемость результата.
  - **Зависимости:** нет; контракт задан дизайном и ADR-0024.
  - **Вероятные файлы:** новые `lib/src/daily_choice/application/daily_choice_day_statuses.dart`, `test/daily_choice/application/daily_choice_day_statuses_test.dart` рядом с существующим контрактом `daily_choice_catalog.dart`.
  - **Размер:** S.

- [ ] 1.3 Реализовать агрегатное чтение состояний дней в Drift на согласованном снимке
  - **Критерии приёмки:**
    - Адаптер предоставляет операцию с контрактом 1.1: агрегирует `daily_choices` по дате через `MIN(is_completed)` и индекс `daily_choices_date_creation_order`, в транзакции общей очереди возвращает ревизию снимка. Выборы, пути и участники не материализуются; схема БД не меняется.
    - Все выборы даты учитываются независимо от архивирования участников и шагов пути. Даты декодируются через `CalendarDate.parseCanonical`, проверяются диапазон и значения выполнения; повреждение даёт отказ всего чтения. Категория отказа определяется через `classifySqliteFailure` и попадает в событие 1.2.
    - Проверки на настоящем SQLite подтверждают три состояния дня, включительные границы, исключение посторонних дат, ревизию после команды и отказ без частичного результата при недопустимой сохранённой дате. Трассировка большого набора подтверждает ограниченную материализацию агрегатов и поиск диапазона по индексу без чтения путей.
  - **Проверка:**
    - `mise exec --no-deps -- flutter test test/graph/data/drift_daily_choice_day_statuses_test.dart test/graph/data/drift_daily_choice_day_statuses_read_cost_test.dart`.

- [ ] 1.7 Согласовывать отметки периода с подтверждёнными ревизиями в отдельной модели представления
  - **Критерии приёмки:**
    - Модель живёт вместе со страницей, получает репозиторий и координатор через существующую сборку Riverpod и начинает чтение окна от начальной выбранной даты каталога. Смена месяца просмотра вызывает чтение; смена представления и просмотр внутри месяца после успеха — нет. Модель не читает выдачу каталога.
    - Любая новая подтверждённая ревизия вызывает чтение без разбора видов изменений. Одновременно выполняется не больше одного запроса; ответ прежнего окна или старее обязательной ревизии отбрасывается, затем читается текущее окно. После освобождения модели подписка прекращается и поздний ответ не публикуется.
    - Последний успешный результат сохраняется при обновлении и отказе, а успех целиком заменяет его и снимает признак отказа. При отсутствии результата дни не получают отметок. После отказа любое изменение просмотра или новая ревизия запускает новое чтение, без видимого состояния загрузки и ручного повтора.
  - **Проверка:**
    - `mise exec --no-deps -- flutter test test/daily_choice/presentation/catalog/daily_choice_calendar_day_marks_view_model_test.dart`: управляемые ответы репозитория, смена окна во время чтения, новая ревизия до ответа, команда без изменения дневных выборов, отказ с прежним результатом и без него, восстановление и освобождение модели.
    - При использовании принятой в проекте генерации провайдера: `mise exec --no-deps -- dart run build_runner build --delete-conflicting-outputs`.
  - **Зависимости:** контракты 1.1, 1.4 и окно 1.6; подменённый репозиторий проверяет модель, подключение реального адаптера проверяют задачи 1.12–1.13.
  - **Вероятные файлы:** новые `lib/src/daily_choice/presentation/catalog/daily_choice_calendar_day_marks_view_model.dart`, `lib/src/daily_choice/presentation/catalog/daily_choice_calendar_day_marks_state.dart`, соответствующий generated-файл провайдера, `test/daily_choice/presentation/catalog/daily_choice_calendar_day_marks_view_model_test.dart`.
  - **Размер:** M.

- [ ] 1.11 Подключить отметки к странице каталога с независимым управлением просмотром и выдачей
  - **Критерии приёмки:**
    - Страница наблюдает модель отметок и передаёт её результат календарю. Свайп, команды шапки, смена представления и выбор дня проходят через одну точку изменения просмотра; начальные окна страницы и модели совпадают без изменения провайдера во время построения.
    - Перелистывание и смена представления не меняют выбранную дату, фильтр выполнения и выдачу и не вызывают её чтения; выбор дня сохраняет существующее поведение. Фильтр выполнения не отсекает выборы из отметок. Смена локали сохраняет просмотр и условия каталога.
    - После получения окна отметки соседней недели и месяца видны уже при частичном перетаскивании. При выходе за полученное окно дни без данных временно остаются без отметок; последние полученные отметки сохраняются до нового ответа.

    - В profile-сборке на устройстве с большим синтетическим личным графом измерена длительность чтения максимального окна через событие 1.2: зафиксированы устройство, объём данных и наблюдаемые длительности при просмотре и после команд. Результаты позволяют оценить пригодность подхода; при выявленной необходимости покрывающего индекса готовность не объявляется, вопрос выносится отдельно согласно Risks дизайна.
    - Полные проверки и строгая валидация изменения проходят; generated-файлы воспроизводимы, схема и сохранённые данные не изменены. Результаты и ограничения измерений сообщены в сессии без отдельного отчётного документа.
  - **Проверка:**
    - `mise run check` и, после фиксации реализации в чистой рабочей копии, `mise run codegen-check`.

    - `mise exec --no-deps -- flutter run --profile -d <идентификатор-устройства>`: измерение из Risks дизайна, просмотр недели и месяца, частичный свайп, изменение выбора, проверка экранным диктором и с увеличенным текстом.
