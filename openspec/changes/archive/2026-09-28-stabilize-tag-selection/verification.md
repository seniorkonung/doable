# Проверка стабильного выбора тегов

Проверено 28 сентября 2026 года. Ревизия продуктового кода: `1c4f584`; Flutter 3.47.1, Dart 3.13.1.

## Воспроизведение и исправление

- До исправления промежуточные кадры последовательного выбора сдвигали список на 100–180 пикселей. После исправления 10 виджетных регрессионных сценариев сохраняют строки, геометрию и прокрутку; каталог из 132 тегов читается один раз.
- Прежнее чтение возвращало 100 из 137 тегов. Полные снимки теперь проверяются без усечения, с неизменяемыми списками, порядком создания и ревизией. Повреждение данных после сотой строки также отклоняется.
- Восемь проверок обновления выбранного тега первоначально падали. После согласования выбора с полным снимком все 14 сценариев ViewModel проходят, включая удаление, поздние ответы, смену эпохи и сохранение ошибки наблюдения.
- Уведомление об успешном создании перекрывало кнопку назначения. Постоянная область действия перенесена в нижнюю область `Scaffold`; четыре сквозных сценария создания и назначения проверяют доступность кнопки для нажатия.

Использованы документированные контракты [ScrollController](https://api.flutter.dev/flutter/widgets/ScrollController-class.html), [нижней области Scaffold](https://api.flutter.dev/flutter/material/Scaffold/bottomNavigationBar.html) и [транзакций Drift](https://drift.simonbinder.eu/dart_api/transactions/).

## Проверки проекта

- Целевые тесты данных, контрактов, пользовательских сценариев, доступности и регрессий проходят.
- `mise run codegen-check`: успешно; повторная генерация не изменила рабочее дерево.
- `openspec validate stabilize-tag-selection --strict`: успешно.
- Итоговый `mise run check`: успешно. Форматирование, проверка CI и анализ Dart прошли; **2381 тест прошёл без отказов**.

Первый общий прогон обнаружил устаревшие шаги поиска кнопок продолжения в проверках доступности и фикстуру позднего ответа с неполным каталогом. Они переведены на полный снимок с сохранением проверок семантики и защиты назначения; соответствующие 70 тестов проходят.

Тест с пятью последовательными дочерними процессами превысил внешний стандартный лимит 30 секунд при одновременной сборке Android. Для этого теста применён существующий в соседних сценариях `Timeout.none`; каждый дочерний процесс по-прежнему ограничен ожиданием READY 45 секунд и завершения 60 секунд. Отдельный повтор прошёл за 18,90 секунды. Продуктовый код ради этого отказа не менялся.

## Проверка Android

Во временном Android-эмуляторе API 36 с настоящим файловым SQLite выполнены:

- `flutter test integration_test/tag_selection_stability_test.dart -d emulator-5580 --no-pub --timeout 10m`: 4 сценария прошли. Проверены намерения и долговременные связи, русский и английский интерфейс, масштаб текста 2,5, промежуточные кадры выбора, прокрутка, отсутствие записей назначений и единственное чтение каталога из 132 тегов.
- В составе `flutter test integration_test -d emulator-5580 --no-pub --concurrency=1 --timeout 10m` прошла проверка полного каталога из 10 000 тегов и прокрутки. Обычный каталог получает все строки одним SELECT; пользовательские данные в диагностику не попадают.
- Обычное приложение запущено через `flutter run`; Dart MCP подтвердил успешный hot reload и отсутствие ошибок выполнения.

В первой попытке устройство с увеличенным текстом требовало больше стандартных 50 шагов тестового помощника для достижения последней строки. Увеличен только бюджет прокрутки теста; повтор всех четырёх сценариев прошёл. Временный эмулятор остановлен и удалён.

Физический телефон не подключён. Измерения времени кадров получены в debug-режиме эмулятора и не являются оценкой производительности физического устройства.
