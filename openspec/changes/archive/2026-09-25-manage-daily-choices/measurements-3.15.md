# Измерения входа от действия — задача 3.15

Измерение выполнено 24 сентября 2026 года командой из задачи 3.15: четыре указанных Flutter-теста в одном запуске. Среда: Linux 7.0.0-31-generic, x86_64, Intel Core i5-9300H (8 логических процессоров), Flutter 3.47.1, Dart 3.13.1, SQLite 3.53.4. Хранилище тестов — настроенная база SQLite в памяти. Время ниже — одно наблюдение на этой машине, а не порог приёмки.

| Сценарий | Фикстура | Наблюдаемое время |
| --- | --- | --- |
| Первая порция действий | 3000 активных намерений, 3 готовы, текстовый фильтр, порция 2 | 7929 мкс; COUNT 2366 мкс, SELECT 1448 мкс |
| Продолжение каталога | Та же фикстура, одна оставшаяся строка | 5864 мкс; повторного COUNT нет |
| Первая порция нижнего обхода | 1360 намерений, 1520 связей, 161 входящая связь действия, циклы, порция 20 | 4104 мкс |
| Продолжение нижнего обхода | Та же фикстура, порция 20 | 3434 мкс |
| Проверка нижнего черновика | Суффикс из 1198 шагов на той же фикстуре | 18 895 мкс |
| Ожидание следующей команды общего исполнителя | Команда поставлена сразу после чтения нижней порции | 6076 мкс; само чтение до ответа — 4346 мкс |

Закрытый SQL trace показал: первая порция каталога возвращает в Dart не более трёх строк запроса (`LIMIT` включает запасную строку), счётчик — одну; продолжение возвращает одну строку. Фильтр готовности находится в SQL запроса порции и счётчика до `LIMIT`. Первая порция нижнего обхода материализует не более 21 строки каждого чтения; запрос кандидатов не содержит рекурсивного перечисления путей. При длинном суффиксе отдельная проверка черновика закономерно читает 1199 намерений и 1198 связей самого подтверждаемого префикса, а запрос следующего перехода возвращает одну строку. В тесте изолятного соединения цикл событий UI-изолятора обслужен до ответа и верхнего, и нижнего запроса. Между чтениями общего исполнителя выполняется команда графа.

Фактические планы `EXPLAIN QUERY PLAN` для измеренных запросов:

```text
Каталог, COUNT: SCAN intentions USING INDEX intentions_active_updated_at_desc_id_asc
Каталог, порция: SCAN intentions USING INDEX intentions_active_created_at_desc_id_asc
Нижний обход: SEARCH r USING INDEX long_term_relations_related_group_order (related_intention_id=?) | LIST SUBQUERY 2 | SCAN json_each VIRTUAL TABLE INDEX 1: | CREATE BLOOM FILTER | SEARCH source USING INDEX sqlite_autoindex_intentions_1 (id=?) | USE TEMP B-TREE FOR ORDER BY
```

Ограничение порции ограничивает переданные строки, но не стоимость поиска: фильтр редкой готовности требует прохода по индексу активного каталога, а сортировка входящих связей использует временное дерево. Длинный суффикс увеличивает стоимость проверки пропорционально длине уже выбранного пути; предел порции глубину пути не ограничивает. Тесты диагностики проверили стадии и категории успешных и отклонённых нижних чтений, проверки пути и создания, отсутствие пользовательского содержимого в сериализованных событиях и неизменность предметного результата при отказе `DiagnosticsSink`.
