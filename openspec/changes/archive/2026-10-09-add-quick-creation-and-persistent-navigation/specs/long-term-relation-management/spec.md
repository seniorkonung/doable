## ADDED Requirements

### Requirement: Входы в создание долговременной связи
Создание долговременной связи SHALL начинаться из группы связей на странице активного намерения или режимом «Новая связь» кнопки быстрого создания по `quick-creation`. При входе из исходящей группы текущее намерение SHALL быть заранее выбрано исходным участником, из входящей — связанным; обе роли MUST оставаться доступными для замены. Режим «Новая связь» SHALL открывать форму без выбранных участников, типа, приоритета и описания.

Поиск участника по требованию «Совместный поиск участника долговременной связи» MUST быть доступен для любой роли независимо от того, выбран ли участник другой роли. Пока другой участник не выбран, поиск MUST NOT исключать ни одно допустимое намерение; после его выбора он MUST исключаться по идентификатору. Отправка MUST оставаться недоступной, пока не выбраны оба участника, тип и приоритет.

Форма создания SHALL предоставлять явное доступное действие «Отменить создание», пока команда не принята или завершилась отказом, а во время принятой отправки — «Выйти из создания» с объяснением, что сохранение продолжится. Эти действия SHALL завершать собственный поток по требованию «Выход из потока создания» из `app-navigation`; обещание не создавать связь MUST относиться только к отмене без выполняющейся или успешно завершённой команды. Закрытие поиска участника без выбора MUST возвращать прежнюю форму с её черновиком и MUST NOT отменять всё создание. Изменение существующей связи MUST сохранять свои действия и контракт закрытия.

#### Scenario: Связь из пустой формы
- **GIVEN** активны намерения «Быть здоровым» и «Много ходить»
- **WHEN** пользователь в режиме «Новая связь» выбирает «Быть здоровым» исходным участником, «Много ходить» связанным, тип «нужно» и приоритет P2 и сохраняет форму
- **THEN** система сохраняет связь «Чтобы быть здоровым, нужно много ходить» с приоритетом P2

#### Scenario: Первый участник выбирается без исключения
- **GIVEN** форма открыта без выбранных участников
- **WHEN** пользователь открывает поиск связанного участника
- **THEN** доступны все активные намерения
- **AND** после выбора «Много ходить» связанным участником поиск исходного участника не предлагает «Много ходить»

#### Scenario: Вход из исходящей группы
- **GIVEN** открыта страница активного намерения «Быть здоровым»
- **WHEN** пользователь начинает создание связи из исходящей группы
- **THEN** «Быть здоровым» выбрано исходным участником, а связанный участник, тип и приоритет не выбраны

### Requirement: Открытие созданной связи
Подтверждённое успешное создание долговременной связи в сохраняющейся сессии формы SHALL открывать её подробный просмотр по идентификатору ровно один раз по требованию «Открытие созданной сущности» из `app-navigation`, независимо от входа. Форма MUST закрываться и MUST NOT оставаться в истории возврата. Страница намерения, с которой начато создание, MUST при возвращении показывать согласованные счётчики и группы связей по действующим правилам.

До подтверждённого успеха, в том числе при ошибке, система MUST NOT открывать подробный просмотр будущей связи, а форма MUST сохранять черновик по требованию «Подтверждённые результаты и незавершённые операции». Если пользователь покинул форму до результата, поздний успех MUST NOT открывать подробный просмотр или менять текущую страницу. Результат MUST предъявляться по действующим правилам однократного предъявления независимо от перехода.

#### Scenario: Связь со страницы намерения открывается после создания
- **GIVEN** на странице «Быть здоровым» пользователь создаёт из исходящей группы связь «нужно» к «Много ходить»
- **WHEN** создание подтверждено
- **THEN** открыт подробный просмотр связи «Чтобы быть здоровым, нужно много ходить»
- **AND** действие «назад» возвращает на страницу «Быть здоровым», где исходящая группа и её счётчик учитывают новую связь

#### Scenario: Отказ не открывает подробный просмотр
- **GIVEN** направленная пара выбранных участников уже занята другой связью
- **WHEN** создание отклонено
- **THEN** подробный просмотр не открывается, форма сохраняет участников, тип, приоритет и описание и позволяет открыть существующую связь

#### Scenario: Уход до результата не меняет страницу
- **GIVEN** отправка формы принята, а пользователь покинул форму до результата
- **WHEN** связь успешно создана
- **THEN** текущая страница не меняется, а результат предъявляется один раз по действующим правилам
