# Индексируемый порядок назначений получателя (задача 2.28)

Источник: автоматизированный тест `test/graph/data/drift_tag_assignment_read_cost_test.dart`; машинные результаты — [assignment-order-read-cost.jsonl](assignment-order-read-cost.jsonl). Тест выполнен на файловых SQLite-базах в Linux x64, Dart 3.13.1, SQLite 3.53.4, в режиме Flutter test (`debug`), с журналом `delete`. Размеры фикстур: 203 тега / 576 назначений / 532480 байт и 1203 тега / 3409 назначений / 2088960 байт. Для каждого размера есть плотные (каждый тег) и разреженные (каждый второй тег у намерения, каждый третий у долговременной связи) назначения обоих видов получателя.

Проверены размеры порции 1, 50 и 100, первые, средние и последние страницы. Для каждого случая тест выполняет пять чтений страницы, фиксирует длительность всего вызова репозитория, число материализованных строк и `EXPLAIN QUERY PLAN`. Полный обход сверяется с ожидаемыми идентификаторами без пропусков и повторов. Основной запрос ищет в `tag_assignments_intention_order` либо `tag_assignments_long_term_relation_order` по получателю; продолжение добавляет диапазон `tag_creation_sequence > ?`. В плане нет временной B-деревной сортировки или прохода таблицы `tags` ради порядка. Найденный тег читается отдельным индексным поиском по id.

Инструментальная SQLite-функция, добавленная к предикату основного запроса без изменения его плана, считает посещённые строки назначений. На обеих фикстурах и у обоих видов получателя число посещений первой и средней страницы ограничено `pageSize + 1`: соответственно 2, 51 и 101. У последней страницы оно равно числу оставшихся строк (от 1 до 101). Таким образом, при фиксированной порции работа основного индексного прохода в этих фикстурах не растёт линейно с общим числом тегов или назначений получателя. Это наблюдение о посещениях и плане, а не утверждение о постоянном времени выполнения SQL.

Диапазоны медиан пяти полных вызовов репозитория для страниц 1/50/100: при 203 тегах — 633–1791 / 827–3274 / 1239–3882 мкс; при 1203 тегах — 586–1599 / 583–1129 / 571–2614 мкс. Измерения выполнялись рядом с другими тестами и показывают разброс среды, поэтому по этим длительностям нельзя выводить гарантированную задержку устройства.

Проверка отсутствующих ссылок остаётся отдельным `LEFT JOIN` один раз в начале неизменённого обхода. Её инструментальный счётчик проходит все назначения выбранного получателя: 68–1203 посещения в зависимости от плотности и размера фикстуры; эта стоимость отделена от основного запроса и не повторяется на каждой порции. При изменении хранилища продолжение получает отказ устаревшего снимка, а новая проверка ссылок выполняется снова.
