## Phase 1: Нижняя панель согласована с системной областью

- [x] 1.1 Добавить панели собственный нижний отступ 6 dp, сохранив кнопки высотой 48 dp
  - **Критерии приёмки:**
    - `NavBar` получает внутренние отступы 6 dp сверху и снизу; верхняя линия занимает отдельный 1 dp. `DoableMetrics.navHeight` и производная `AppNavigationBar.height` равны 61 dp без системного отступа, согласно решению 1 в [дизайне](design.md).
    - Полная высота равна `61 dp + SafeArea.bottom`; фон `raised` покрывает безопасную область. Собственный отступ сохраняется и при нулевом, и при ненулевом системном отступе, а размеры кнопок и их доступные действия не меняются.
  - **Проверка:**
    - Выполнить `mise exec -- flutter test test/app/navigation/app_navigation_bar_test.dart`; дополнить существующие проверки измерением кнопок и собственных отступов при нулевом и ненулевом нижнем inset.
  - **Зависимости:** Нет.
  - **Вероятные файлы:** `lib/src/design_system/components/nav_bar.dart`, `lib/src/design_system/doable_metrics.dart`, `test/app/navigation/app_navigation_bar_test.dart`.
  - **Оценка объёма:** M.

- [x] 1.2 Связать оформление системной навигации Android с темой общей панели приложения
  - **Критерии приёмки:**
    - `AppNavigationBar` задаёт стиль нижней системной области по решению 2 в [дизайне](design.md): цвет панели и разделителя равен `raised` текущей темы, светлые системные элементы на тёмном фоне и тёмные на светлом, `systemNavigationBarContrastEnforced: false`. Стиль охватывает безопасную область и обновляется при смене темы без пересоздания открытой страницы. Применимость полей по API обеспечивает Flutter; дополнительный канал определения версии Android в Dart не вводится.
    - Верхняя системная строка сохраняет оформление своего владельца — `AppBar` или страницы. Нижний стиль применяется общим компонентом как в оболочке, так и на обычных страницах, в границах [ADR-0020](../../../docs/adr/0020-host-persistent-navigation-in-ordinary-page-scaffolds.md) и [ADR-0030](../../../docs/adr/0030-keep-design-system-components-presentational.md).
    - Проверен действующий режим окна на API 29+ в используемом Flutter и конфигурации Android. Явное включение edge-to-edge при запуске добавлено только при установленной необходимости для этих версий; оно не считается способом совместимости API 24–28. Поддержка API 24+ и нативная политика ориентации и размера окна по [ADR-0031](../../../docs/adr/0031-restrict-phones-to-portrait-full-screen.md) сохраняются.
  - **Проверка:**
    - Выполнить `mise exec -- flutter test test/app/navigation/app_navigation_bar_test.dart`; проверить цвет панели и разделителя, яркость кнопок и обновление стиля при смене темы, включая размещение панели со `Scaffold.appBar`.
    - Сверить режим окна с закреплённым Flutter и `android/app/build.gradle.kts`; не считать переданный Flutter-стиль подтверждением фактического цвета системной области. Проверки Android входят в задачи 1.3 и 1.5.
  - **Зависимости:** 1.1.
  - **Вероятные файлы:** `lib/src/app/navigation/app_navigation_bar.dart`, `test/app/navigation/app_navigation_bar_test.dart`; `lib/main.dart` — только при необходимости явной настройки режима окна.
  - **Оценка объёма:** M.

- [ ] 1.3 Обеспечить совместимое оформление системных кнопок на Android 7–9 без повышения минимальной версии
  - **Критерии приёмки:**
    - По решению 2 [дизайна](design.md) дневные и ночные `LaunchTheme` и `NormalTheme` задают непрозрачную чёрную навигационную подложку. На API 24–25 сохраняются штатные светлые кнопки, независимо от темы Flutter; прозрачная подложка и тёмные кнопки не используются как решение для этих версий.
    - На API 26–28 системная область остаётся вне окна Flutter и получает цвет текущего `raised` и соответствующую яркость кнопок из общей панели. Системный отступ не добавляется повторно, собственные 6 dp сохраняются. `minSdk` остаётся 24, а нативная политика дисплея не меняется.
    - На API 24, 26 и 28 подтверждены фактический фон, различимость кнопок и безопасное размещение на главной странице и в каталоге по разделу 6 дизайна. Недоступная граница API оставляет задачу незавершённой; аннотация Flutter не заменяет наблюдение результата Android.
  - **Проверка:**
    - Выполнить `mise exec -- flutter build apk --debug` и установить сборку на устройства или эмуляторы API 24, 26 и 28 с тремя кнопками. Проверить запуск и возврат после клавиатуры и нижнего листа; где доступна системная настройка темы — обе темы и переключение между ними.
    - На API 24 наблюдать тёмную подложку со светлыми кнопками при светлом интерфейсе; на API 26 и 28 — совпадение фона с панелью и контраст кнопок. Убедиться, что системная область учтена один раз и собственный отступ не исчез. Сообщить версии ОС и результаты в сессии без отдельного отчётного документа.
  - **Зависимости:** 1.1, 1.2.
  - **Вероятные файлы:** `android/app/src/main/res/values/styles.xml`, `android/app/src/main/res/values-night/styles.xml`.
  - **Оценка объёма:** M.

- [ ] 1.4 Подтвердить размещение содержимого и сообщений над обновлённой панелью на корневых и обычных страницах
  - **Критерии приёмки:**
    - Оболочка продолжает передавать высоту через `AppNavigationBar.height` в `AppShellTabInsets`, а обычные страницы используют `Scaffold.bottomNavigationBar`; отдельные поправки на 6 dp в потребителях не появляются. Выдача и сообщения остаются доступными над панелью и клавиатурой.
    - На нижней границе поддержки по `app-appearance` оба каталога сохраняют доступность всех дней, ручки, сообщения об отказе отметок и прокрутки выдачи по [спецификации календаря](specs/daily-choice-management/spec.md). Применяются существующие проверки раскладки; гарантии не ослабляются ради новой высоты панели.
  - **Проверка:**
    - Выполнить `mise exec -- flutter test test/app/navigation/app_shell_tab_insets_test.dart test/app/navigation/app_shell_layout_test.dart test/app/navigation/ordinary_page_scaffold_test.dart test/daily_choice/presentation/catalog/daily_choice_catalog_supported_layout_test.dart`.
    - При необходимости изменить только ожидания, относящиеся к прежней высоте панели, или дополнить существующую проверку отсутствующей гарантией; уже покрытые случаи не дублировать.
  - **Зависимости:** 1.1, 1.2, 1.3.
  - **Вероятные файлы:** `test/app/navigation/app_shell_layout_test.dart`, `test/app/navigation/ordinary_page_layout_scenarios.dart`, `test/app/navigation/ordinary_page_scaffold_test.dart`, `test/daily_choice/presentation/catalog/daily_choice_catalog_supported_layout_test.dart`; изменения нужны только при обнаруженном пробеле или устаревшем ожидании.
  - **Оценка объёма:** M.
