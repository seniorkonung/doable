## Phase 1: Нижняя панель согласована с системной областью

- [ ] 1.1 Добавить панели собственный нижний отступ 6 dp, сохранив кнопки высотой 48 dp
  - **Критерии приёмки:**
    - `NavBar` получает внутренние отступы 6 dp сверху и снизу; верхняя линия занимает отдельный 1 dp. `DoableMetrics.navHeight` и производная `AppNavigationBar.height` равны 61 dp без системного отступа, согласно решению 1 в [дизайне](design.md).
    - Полная высота равна `61 dp + SafeArea.bottom`; фон `raised` покрывает безопасную область. Собственный отступ сохраняется и при нулевом, и при ненулевом системном отступе, а размеры кнопок и их доступные действия не меняются.
  - **Проверка:**
    - Выполнить `mise exec -- flutter test test/app/navigation/app_navigation_bar_test.dart`; дополнить существующие проверки измерением кнопок и собственных отступов при нулевом и ненулевом нижнем inset.
  - **Зависимости:** Нет.
  - **Вероятные файлы:** `lib/src/design_system/components/nav_bar.dart`, `lib/src/design_system/doable_metrics.dart`, `test/app/navigation/app_navigation_bar_test.dart`.
  - **Оценка объёма:** M.

- [ ] 1.2 Связать оформление системной навигации Android с темой общей панели приложения
  - **Критерии приёмки:**
    - `AppNavigationBar` задаёт стиль нижней системной области по решению 2 в [дизайне](design.md): прозрачный фон там, где платформа учитывает цвет, светлые системные элементы на тёмном фоне и тёмные на светлом, `systemNavigationBarContrastEnforced: false`. Стиль охватывает безопасную область и обновляется при смене темы без пересоздания открытой страницы.
    - Верхняя системная строка сохраняет оформление своего владельца — `AppBar` или страницы. Нижний стиль применяется общим компонентом как в оболочке, так и на обычных страницах, в границах [ADR-0020](../../../docs/adr/0020-host-persistent-navigation-in-ordinary-page-scaffolds.md) и [ADR-0030](../../../docs/adr/0030-keep-design-system-components-presentational.md).
    - Проверен действующий режим окна в используемом Flutter и конфигурации Android. Явное включение edge-to-edge при запуске добавлено только при установленной необходимости по дизайну; нативная политика ориентации и размера окна по [ADR-0031](../../../docs/adr/0031-restrict-phones-to-portrait-full-screen.md) сохраняется.
  - **Проверка:**
    - Выполнить `mise exec -- flutter test test/app/navigation/app_navigation_bar_test.dart`; проверить системный стиль в обеих темах и его обновление при смене темы, включая размещение панели со `Scaffold.appBar`.
    - Сверить режим окна с закреплённым Flutter и `android/app/build.gradle.kts`; не считать переданный Flutter-стиль подтверждением фактического цвета системной области. Проверка Android входит в задачу 1.4.
  - **Зависимости:** 1.1.
  - **Вероятные файлы:** `lib/src/app/navigation/app_navigation_bar.dart`, `test/app/navigation/app_navigation_bar_test.dart`; `lib/main.dart` — только при необходимости явной настройки режима окна.
  - **Оценка объёма:** M.

- [ ] 1.3 Подтвердить размещение содержимого и сообщений над обновлённой панелью на корневых и обычных страницах
  - **Критерии приёмки:**
    - Оболочка продолжает передавать высоту через `AppNavigationBar.height` в `AppShellTabInsets`, а обычные страницы используют `Scaffold.bottomNavigationBar`; отдельные поправки на 6 dp в потребителях не появляются. Выдача и сообщения остаются доступными над панелью и клавиатурой.
    - На нижней границе поддержки по `app-appearance` оба каталога сохраняют доступность всех дней, ручки, сообщения об отказе отметок и прокрутки выдачи по [спецификации календаря](specs/daily-choice-management/spec.md). Применяются существующие проверки раскладки; гарантии не ослабляются ради новой высоты панели.
  - **Проверка:**
    - Выполнить `mise exec -- flutter test test/app/navigation/app_shell_tab_insets_test.dart test/app/navigation/app_shell_layout_test.dart test/app/navigation/ordinary_page_scaffold_test.dart test/daily_choice/presentation/catalog/daily_choice_catalog_supported_layout_test.dart`.
    - При необходимости изменить только ожидания, относящиеся к прежней высоте панели, или дополнить существующую проверку отсутствующей гарантией; уже покрытые случаи не дублировать.
  - **Зависимости:** 1.1, 1.2.
  - **Вероятные файлы:** `test/app/navigation/app_shell_layout_test.dart`, `test/app/navigation/ordinary_page_layout_scenarios.dart`, `test/app/navigation/ordinary_page_scaffold_test.dart`, `test/daily_choice/presentation/catalog/daily_choice_catalog_supported_layout_test.dart`; изменения нужны только при обнаруженном пробеле или устаревшем ожидании.
  - **Оценка объёма:** M.

- [ ] 1.4 Проверить готовность первой фазы и собрать Android-приложение для проверки системного фона
  - **Критерии приёмки:**
    - Выполнено условие перехода первой фазы из [плана](plan.md): проверки панели и её потребителей проходят, раскладка сохраняется, подготовлена APK-сборка с обновлённым оформлением. Существующие примеры панели в Widgetbook показывают новый отступ в обеих темах.
    - На REDMI Note 15 Pro+ 5G проверены фон и различимость системных элементов при жестах и трёх кнопках по разделу 6 дизайна; результат и версии Android/HyperOS сообщены в сессии. Если устройство недоступно, в итогах явно сохранена обязательная проверка Redmi для завершения фазы 3; готовность сборки не объявляется подтверждённым исправлением светлой полосы.
  - **Проверка:**
    - Выполнить `mise run check` и `openspec validate polish-calendar-and-navigation --strict`.
    - Выполнить `mise exec -- flutter build apk --release`; сообщить путь к полученному APK для проверки на телефоне.
    - Открыть существующие примеры панели через `mise run widgetbook`, проверить отступ и размеры кнопок в обеих темах. Автоматические тесты для Widgetbook не добавлять.
    - На доступном Redmi проверить главную страницу и каталог в обоих режимах навигации: запуск сразу в светлой и тёмной темах, смену темы, возврат после клавиатуры и нижнего листа. Если светлая область остаётся, продолжить диагностику окна и итогового системного стиля по дизайну; результаты сообщать в сессии без отдельного отчётного документа.
  - **Зависимости:** 1.1, 1.2, 1.3.
  - **Вероятные файлы:** Нет, проверка и сборка; используется существующий `widgetbook/lib/navigation/app_navigation_bar_use_cases.dart`.
  - **Оценка объёма:** S.
