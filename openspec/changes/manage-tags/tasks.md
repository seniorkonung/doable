Пакет раскрывает только первую фазу [плана](plan.md). Требуемое поведение задают [спецификация тегов](specs/tag-management/spec.md) и связанные правила [намерений](specs/intention-management/spec.md) и [долговременных связей](specs/long-term-relation-management/spec.md); устройство модулей — [дизайн](design.md), архитектурные ограничения — [манифест ADR](adr.md) и перечисленные в нём решения.

В этой фазе доступны общий каталог и самостоятельный жизненный цикл тега. Полный контракт таблицы назначений и удаления тега проверяется через фикстуры хранения; пользовательские команды назначения и снятия, выбор получателя, изменения его подробностей и навигация по помеченным сущностям остаются фазам 2–3. Новые пути ниже — предполагаемые файлы внутри границ, выбранных дизайном по образцу существующих модулей. Сгенерированные файлы обновляются штатной генерацией вместе с источниками.

- [x] 4.1 Сохранять типизированный отказ при окончании наблюдения навигации
