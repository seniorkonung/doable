## Findings

### F9 · Medium — Плоскости описания и плиток типа рисуются за пределами прокручиваемой области

- **Evidence:** `TextField.saved` рисует плоскость `fill` через `Ink` без собственного `Material` (`lib/src/design_system/components/text_field.dart:265-275`), так же `OptionTiles` рисует плоскость выбранной плитки, кольцо невыбранной и кольцо фокуса (`lib/src/design_system/components/option_tiles.dart:130-155`). `Ink` рисует на холсте ближайшего `Material`, а `_RenderInkFeatures.paint` во Flutter 3.47.1 обрезает его только размером самого `Material` и рисует под всеми потомками; `InkFeature._paint` пропускает рисование лишь у потомка, которого предок не рисует, и не учитывает обрезку `Viewport`. На странице намерения оба компонента стоят в `SliverToBoxAdapter` «Обзора» (`lib/src/intention/presentation/details/intention_details_page.dart:609`, `:629`), ближайший `Material` — `Scaffold` из `OrdinaryPageScaffold`, а `TopBar` прозрачен (`lib/src/design_system/components/top_bar.dart:286` — `SafeArea` без фона). Закреплённая полоса вкладок закрывает только свою часть, у неё свой `Material` с фоном. ## Review coverage

Политика предъявления. Координатор выбирает политику по виду команды: готовность, архивирование и восстановление создают запись уже без права инициатора, а успех публикуется `IntentionUnannouncedSuccessCompletion` только для согласования и не оставляет непредъявленной записи. Удаление сохраняет политику по умолчанию, модель освобождает право инициатора сразу при принятии. Ветвь `StateError` презентера недостижима: успехи этих видов не становятся предъявляемыми. Других инициаторов готовности, архивирования и восстановления, кроме модели подробных данных, нет. Ответ `AlreadyRunning` делает модель занятой; ответ `Draining` ничего не начинает — он возможен при замене графа, во время которой страница закрыта для взаимодействия, и при завершении процесса.

«Обзор» и правка. Курсор экрана изменения задаёт типизированная цель `IntentionEditFocus`. Отступы описания, плиток, тегов и дат совпадают с задачами 4.5–4.13. Даты переводятся в местное время, год показывается только для другого года, текущий день страница пересчитывает при смене дня. Ключи блока тегов стоят на областях нажатия, «Добавить» и крестики выключаются в прежних условиях. Повторное нажатие плитки до прихода нового снимка безвредно: хранилище отвечает неизменённым успехом, а «только отказ» его не объявляет.

Параметры. Сборщик меню проверен по всем веткам сводки: пояснения архивирования и восстановления по `active` и `longTermTotal`, причина выключенного удаления по `longTermTotal` и `dailyTotal`, ожидание при операции с сохранением причины блокировки. Лист следит за моделью, закрывается при утрате данных только будучи текущим маршрутом; удаление подтверждается `showConfirmDialog`, страница закрывается только своим успехом и только если её маршрут текущий.

Удаление прежнего вида. Команды `rg` из задач 4.22 и 4.23 ничего не находят; ключей прежних кнопок и диалога в `lib` и `test` нет. Ключи ARB совпадают на обоих языках, удалённые строки убраны и из сгенерированной локализации.

Компоненты. Три SVG совпадают с макетом `IntentionPage.dc.html`, эталон каталога иконок содержит только три новых значка. Геометрия, токены, семантика и выключенные состояния `OptionTiles`, `TagChip.medium`, `AddRow`, `TagsSection`, `DatesLine`, `Badge.archived`, `Button.quietBlock`, `PageHead`, `TopBar` с кнопкой-иконкой, опасного `OptionRow` и `OptionsMenu` сверены с README и задачами. Кольцо невыбранной плитки как `Border.all` предписано README `OptionTiles`, поэтому сдвиг содержимого на 1 px не выделен в находку. Свой рендер-объект `AddRow` оправдан выносом области нажатия на 6 за край; его ветвь для письма справа налево — часть корректной раскладки по `Directionality`, а не спекулятивный вариант. Тип `List<TagChip>` у `TagsSection` допускает малый чип, но отдельный тип чипа md потребовал бы несоразмерной перестройки `TagChip` при единственном потребителе. Точка-разделитель в доступном тексте `DatesLine` передаёт видимый текст и не выделена в находку.

Принятые риски. Задача 4.17 добавила кнопку-иконку к варианту со стрелкой «назад», а не новый потребитель панели с компактной кнопкой: условие AR2 сохраняется. Задача 4.15 не изменила область нажатия названия, а пункт «Изменить» в параметрах стал вторым входом в правку: условие AR3 сохраняется, повода для его пересмотра нет. Оформление требований (AR1) фаза не меняет.
