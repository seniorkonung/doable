Задача 2.26 изменения `add-quick-creation-and-persistent-navigation`, 2026-10-08. Проверена ревизия `bb9ae02b59389affb95a267db72358e2beb5194f`, содержащая исправленный тестовый контракт доступности кандидатов из 2.25 (дерево Git `5c41d51d638f87e0e543a0dff79069633cec983b`). Все проверки выполнены на чистой рабочей копии этой ревизии до изменения отчёта и отметки 2.26.

Условие `Ready to advance` фазы «Phase 2: Создание сохраняет исходную историю при любом входе» из [плана](../../openspec/changes/add-quick-creation-and-persistent-navigation/plan.md) подтверждено свежими результатами. Все четыре входа готовы для композиции Phase 3. Подтверждена только Phase 2; изменение в целом остаётся незавершённым, поскольку Phase 3 ещё не представлена пакетом задач.

Прежнее утверждение о достижимости кандидатов в отчёте на `48c896a5f78b7e95d1147eae6391a9985e8d788f` не используется как доказательство: прежний `find.text('Гулять').first` находил одноимённый ввод, а не строку выдачи. Новое свидетельство — реализованный контракт 2.25 на указанной ревизии и его свежие успешные прогоны, включая 96 сочетаний именно строк кандидатов, два отрицательных контроля, четыре потока, навигацию, сообщения, генерацию, анализ и release-сборку. ## Доступность кандидатов и отмены после исправления 2.25

Свежие прогоны на `bb9ae02b59389affb95a267db72358e2beb5194f` включают [поиск действия](../../test/daily_choice/presentation/action_picker/daily_choice_action_picker_page_test.dart) и [поиск основания](../../test/daily_choice/presentation/source_picker/daily_choice_source_picker_page_test.dart). Обе страницы вызывают один [регрессионный контракт](../../test/daily_choice/presentation/daily_choice_picker_context_test_support.dart) для `InitialDailyChoicePickerContext`. Для каждой страницы проверены 2 локали × 2 масштаба текста × 3 размера × 2 варианта безопасных отступов × 2 начальных состояния клавиатуры = **48 сочетаний**, всего **96**.

Матрица охватывает русский и английский интерфейсы, текст 1.0 и 2.6, телефон 400×800 и планшет 800×1280 / 1280×800 при DPR 1, клавиатуру 0 / 260 логических пикселей, отступы 0 / 0 и 24 сверху / 32 снизу. В каждом сочетании клавиатура появляется и скрывается на том же экземпляре страницы: 0 → 260 → 0 либо 260 → 0 → 260. Во всех состояниях проверяются строка кандидата и текстовая отмена; затем отдельный запуск в исходном сочетании подтверждает выбор ожидаемого ID обычным нажатием строки.

| Проверка исправленного контракта | Связь с условием готовности Phase 2 |
| --- | --- |
| `_initialCandidate` находит `IntentionSummaryView` внутри верхней страницы с конкретным `InitialDailyChoicePickerContext` и ключом ожидаемого `IntentionId`. Поле сохраняет «Гулять»; его `EditableText` явно отличается от текста внутри строки. Первое или последнее текстовое совпадение не служит доказательством доступности кандидата. | Проверяется нужная строка выдачи собственного поиска; одноимённый ввод и нижележащий поиск не подменяют кандидата. |
| Прокрутка раскрывает именно строку. Она проходит `hitTestable` и имеет `SemanticsAction.tap`; область нажатия 48×48 вокруг её центра находится внутри видимой области над нижним действием и клавиатурой. При крупном тексте высота сводки может превышать высоту области просмотра; проверяется доступная область нажатия. | Кандидат достижим в каждом из 96 сочетаний и после смены состояния клавиатуры. |
| В отдельном запуске каждого сочетания `tester.tap(nextCandidate)` возвращает ожидаемый `IntentionId`, сохраняя исходные `matchId`, нижележащий фильтр «Гул» и отсутствие команды создания. Прямой вызов `onTap` не используется как доказательство достижимости. | Выбор кандидата действительно работает через обычное нажатие и передаёт идентичность намерения. |
| Весь прямоугольник нижней кнопки и её подписи находится в доступной области; действие проходит `hitTestable`, имеет `SemanticsAction.tap` и выполняется обычным `tester.tap`. Случай F1 — телефон 400×800, текст 2.6 и клавиатура с верхней границей y=540 — проходит для обеих страниц. Нижняя граница кнопки совпадает с доступной границей, тело заканчивается над кнопкой; поле и условия тегов достижимы прокруткой. Исключений раскладки и лишнего нижнего отступа нет. | Сохраняются видимость и доступность текстовой отмены из 2.23, включая клавиатуру и безопасные отступы. |
| Отмена прекращает запуск до закрытия, возвращает отсутствие ID и сохраняет точные `matchId` исходной истории, фильтр и выдачу нижележащего поиска. Команд создания нет; поздний обработчик выбора игнорируется. | Отмена убирает только собственный поток и не возобновляет покинутое создание. |

Отрицательное свидетельство — тест «доступный одноимённый ввод не скрывает недостижимость строки кандидата», успешно выполненный для каждой реальной страницы. Тестовое перекрытие блокирует строку, оставляя поле доступным. Прежний `find.text('Гулять').first` по-прежнему проходит `hitTestable` и оказывается `EditableText`; строка не проходит `hitTestable`, а новый `_expectPickerCandidateReachable` выдаёт ожидаемый `TestFailure`, который тест перехватывает. Обычное нажатие заблокированной строки не закрывает поиск и не выбирает ID. После снятия перекрытия обычное нажатие той же строки возвращает ожидаемый ID. Это подтверждает чувствительность проверки к недостижимости кандидата; оба контрольных сценария успешны, падений тестового прогона нет.

Верхний крестик отдельно проверен с клавиатурой и текстом 2.6 в обеих локалях. [Проверки запуска](../../test/daily_choice/presentation/daily_choice_creation_launcher_test.dart) в обоих направлениях подтверждают текстовую отмену и крестик над глубокой историей, сохранение чужого черновика, запрет позднего открытия пути и чистое новое открытие поиска. Сценарии самостоятельных поисковых сессий, возврата из подробностей и условий тегов, а также [замены пути](../../test/daily_choice/presentation/daily_choice_path_replacement_flow_test.dart) подтверждают прежний контракт `AuxiliaryDailyChoicePickerContext`: вспомогательный выбор возвращает результат и не отменяет всё создание.

## Частичные отказы открытия дневного выбора

[Матрица завершения](../../test/daily_choice/presentation/daily_choice_creation_completion_test.dart) проверяет каждую точку для `topDown` и `bottomUp` с настоящими стеком приложения, координатором и SQLite. `H` — точные экземпляры страниц до запуска, включая чужой черновик; `Path` и `Confirm` — собственные страницы нового потока.

| Точка отказа | Фактический стек и безопасный результат в обоих направлениях |
| --- | --- |
| До удаления подтверждения | `H, Path, Confirm`: сохранена одна запись, повторная отправка недоступна. Обычное «назад» закрывает подтверждение; оставшийся путь не разрешает правку или новое подтверждение, следующий возврат ведёт в `H`. |
| После удаления подтверждения, до замены корня | `H, Path`: путь остаётся завершённым, повторное создание недоступно; возврат ведёт в `H` без подтверждения потери сохранённых данных. |
| После удаления корня, до установки результата | `H`: показана исходная страница; её история и чужой черновик сохранены. Создание не восстанавливается, запись и переход не повторяются. |
| Поздний отказ после установки результата | Сохраняется конкретный подробный просмотр созданного ID; прежний обработчик не закрывает его и не повторяет переход. Возврат ведёт в `H`. |
| Поздний отказ после выхода и нового создания | Новые идентичность сессии, маршруты и редактируемое состояние остаются без изменений; прежняя запись остаётся единственной. |

В каждом сценарии проверены терминальное состояние, число записей и завершений команды, исходные `matchId`, видимая страница, доступный возврат и отсутствие необработанных исключений. Диагностика новых отказов запуска, завершения и выхода дневного выбора и связи отделена от результата записи; исходное исключение заменяется безопасным сообщением. Проверки исключают секретный текст и UUID из диагностик частичных переходов. Протоколы записи, согласования по ревизии и однократного предъявления сообщений остаются прежними.
