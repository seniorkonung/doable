# Готовность потоков создания Phase 2

Задача 2.24 изменения `add-quick-creation-and-persistent-navigation`, 2026-10-08. Проверена ревизия `9ffa2dd7c45dc24a8b992e6d1434b3603a16c003`, содержащая исправление доступности отмены начального поиска из 2.23 (дерево Git `c1153bc681163039a7a5af1c6d883bf68bae92f4`). Код приложения и тесты совпадают с этой ревизией; контрольная точка меняет только этот отчёт и отметку 2.24.

Условие `Ready to advance` фазы «Phase 2: Создание сохраняет исходную историю при любом входе» из [плана](../../openspec/changes/add-quick-creation-and-persistent-navigation/plan.md) подтверждено свежими результатами. Все четыре входа готовы для композиции Phase 3. Подтверждена только Phase 2; изменение в целом остаётся незавершённым, поскольку Phase 3 ещё не представлена пакетом задач.

Свидетельства 2.22 предшествовали исправлению 2.23 и не используются как подтверждение исправленной компоновки. Все результаты ниже получены заново на указанной ревизии, включая матрицу начальных поисков, четыре потока создания, навигацию, сообщения, генерацию, анализ и release-сборку.

Обычное «назад» из подтверждения до отправки возвращает прежний путь с возможностью продолжения; скрытие клавиатуры не завершает создание. Явная отмена удаляет только собственный поток и не принимает команду. Выход после принятия оставляет ровно одну выполняющуюся команду у координатора; её поздние успех и отказ не меняют другую или заново открытую сессию. При частичном выходе оставшиеся страницы допускают только безопасный повтор выхода. Эти различия проверены отдельно от успешного открытия результата.

Они вызывают один [регрессионный контракт](../../test/daily_choice/presentation/daily_choice_picker_context_test_support.dart) для `InitialDailyChoicePickerContext`: 48 сочетаний на страницу, всего 96. В каждом сочетании проверяются появление и скрытие клавиатуры на той же странице.

## Частичные отказы открытия дневного выбора

[Матрица завершения](../../test/daily_choice/presentation/daily_choice_creation_completion_test.dart) проверяет каждую точку для `topDown` и `bottomUp` с настоящими стеком приложения, координатором и SQLite. `H` — точные экземпляры страниц до запуска, включая чужой черновик; `Path` и `Confirm` — собственные страницы нового потока.

| Точка отказа | Фактический стек и безопасный результат в обоих направлениях |
| --- | --- |
| До удаления подтверждения | `H, Path, Confirm`: сохранена одна запись, повторная отправка недоступна. Обычное «назад» закрывает подтверждение; оставшийся путь не разрешает правку или новое подтверждение, следующий возврат ведёт в `H`. |
| После удаления подтверждения, до замены корня | `H, Path`: путь остаётся завершённым, повторное создание недоступно; возврат ведёт в `H` без подтверждения потери сохранённых данных. |
| После удаления корня, до установки результата | `H`: показана исходная страница; её история и чужой черновик сохранены. Создание не восстанавливается, запись и переход не повторяются. |
| Поздний отказ после установки результата | Сохраняется конкретный подробный просмотр созданного ID; прежний обработчик не закрывает его и не повторяет переход. Возврат ведёт в `H`. |
| Поздний отказ после выхода и нового создания | Новые идентичность сессии, маршруты и редактируемое состояние остаются без изменений; прежняя запись остаётся единственной. |

В каждом сценарии проверены терминальное состояние, число записей и завершений команды, исходные `matchId`, видимая страница, доступный возврат и отсутствие необработанных исключений. Диагностика новых отказов запуска, завершения и выхода дневного выбора и связи отделена от результата записи; исходное исключение заменяется безопасным сообщением. Проверки исключают секретный текст и UUID из диагностик частичных переходов. Протоколы записи, согласования по ревизии и однократного предъявления сообщений остаются прежними.
