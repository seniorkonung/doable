# ADR-0018: Отделить контекст выбора тегов от постоянных назначений

- Status: proposed
- Originating change: compact-intention-creation
- Date: 2026-10-04

## Контекст

Один компонент выбора тегов должен обслуживать существующее намерение и черновик создания. В первом случае подтверждение выбора сохраняет назначение, во втором — меняет только предполагаемый набор будущего намерения. Создание самого тега в обоих случаях остаётся самостоятельной постоянной операцией.

Принятые [ADR-0013](0013-load-complete-tag-snapshots.md) и [ADR-0009](0009-unify-personal-graph-module-and-revision.md) определяют полные согласованные снимки тегов и единственную границу графа. Они не определяют контракт компонента выбора для объекта, который ещё не создан. Расширять чтение хранилища состоянием черновика или заранее создавать намерение ради повторного использования назначения означало бы смешать эти границы.

## Решение

Компонент выбора получает типизированный контекст интерфейса с закрытыми вариантами просмотра, назначения существующему намерению и добавления в черновик. Список, поиск, выбор кандидата и редактор тегов остаются общими. Контекст определяет признаки включения и узкий контракт явного действия; выбор строки сам по себе не создаёт назначения.

Контекст интерфейса отделён от режимов чтения репозитория. Для существующего намерения адаптер использует сохранённые назначения и команды графа. Для черновика он читает общий каталог и наблюдаемый набор сессии, а подтверждённое добавление меняет только этот набор. Черновик не получает фиктивного идентификатора намерения; его состояние и сессионные ключи не входят в контракт постоянного хранилища.

Вызывающий сценарий собирает нужный контекст из явных зависимостей. Общий компонент не получает весь объект приложения и не решает, когда создавать намерение. Самостоятельное создание тега проходит через существующий модуль графа; новый тег включается в черновик только явным действием. Все назначения будущего намерения записываются при его едином атомарном создании, уже предусмотренном границей ADR-0009.

## Последствия

- Сценарии повторно используют один интерфейс выбора и общие правила чтения, сохраняя разные моменты записи. Новые потребители могут расширять контексты без дублирования страницы и переноса временного состояния в репозиторий.
- Адаптеры назначения и черновика проверяются отдельно: первый сохраняет проверки пары и протокол результатов, второй — принадлежность открытой сессии и доступность изменения её набора.
- Отмена создания намерения освобождает черновик, сохраняя независимо созданные теги. Изменения и удаление тегов требуют согласования отображения по их идентификаторам, без подмены одноимёнными тегами.
- Дублирование страниц создаёт расходящиеся правила выбора. Передача черновика в режим репозитория нарушает границу постоянных данных; предварительное создание намерения оставляет записи после отмены и не отвечает требованию единого сохранения.
