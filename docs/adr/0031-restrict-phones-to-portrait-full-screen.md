# ADR-0031: Ограничить приложение на телефонах портретной ориентацией во весь экран

- Status: proposed
- Originating change: redesign-daily-choice-calendar
- Date: 2026-10-15

## Контекст

Все макеты Doable нарисованы для портретного телефона (390×844). Перевод экранов на дизайн закрепляет части интерфейса по высоте: календарь каталога дневных выборов стоит над списком, а раскрытый месяц занимает около 380 dp. В альбомной ориентации и в половине разделённого экрана он не помещается, а ручка сворачивания уходит за край. Владелец продукта решил не поддерживать эти режимы: приложение на них не рассчитано, а отдельные раскладки для каждого экрана дорого создавать и поддерживать.

Приложение собирается с targetSdk 36 и поддерживает Android начиная с API 24. Для приложений с таким targetSdk [Android 16 игнорирует ограничения ориентации и изменения размера](https://developer.android.com/about/versions/16/behavior-changes-16#ignore-orientation) на дисплеях от 600 dp по короткой стороне. Это поведение не переносится на старые ОС: на API 24–30 `resizeableActivity="false"` запрещает многооконный режим независимо от размера дисплея, а на API 31–35 может включать режим совместимости на большом экране ([поведение многооконного режима по версиям](https://developer.android.com/develop/ui/views/layout/support-multi-window-mode#version-specific)). Поэтому безусловные ограничения общей Activity не обеспечивают телефонную границу.

## Решение

На телефонных дисплеях приложение работает только в портретной ориентации и во весь экран. Ориентацией и изменением размера владеет нативный запуск Android: ограничения действуют с запуска приложения, включая подготовку локального хранилища и её отказ, и не зависят от кода Dart. Телефонный дисплей имеет короткую сторону менее 600 dp, большой — от 600 dp. Категория определяется дисплеем, а не шириной текущего окна приложения; узкое окно планшета не должно получать телефонные ограничения. При смене дисплея складного устройства политика соответствует новому дисплею.

Экраны проектируются для портретной высоты телефона в области поддержки, заданной `app-appearance`. На больших дисплеях ориентацию и размер окна определяет система на всех поддерживаемых Android API; приложение не добавляет запрет поворота или изменения размера. Отдельных раскладок для них нет, и поведение Android 16 не отключается. Безусловная пара `screenOrientation="portrait"` и `resizeableActivity="false"` у общей Activity этому решению не соответствует. Конкретный нативный механизм и его проверки принадлежат решению 6 дизайна изменения.

## Последствия

- Новым экранам не нужны альбомные раскладки и раскладки для половины экрана телефона; закреплённые части можно рассчитывать на портретную высоту.
- Ввод текста в альбомной ориентации и работа рядом с другим приложением на телефоне недоступны.
- На планшетах и раскрытых складных устройствах приложение может поворачиваться и менять размер окна также до Android 16. Это сохранение системных режимов, а не гарантия раскладки в произвольном окне; отдельная адаптация больших экранов потребует нового решения.
- Проверки различают телефонный и большой дисплеи, включая границу 600 dp и применение политики с запуска. Поворот и разделение экрана проверяются на Android Activity для обеих категорий на версиях API 24–30, API 31–35 и API 36. Телефонные ограничения проверяются также при подготовке хранилища и её отказе; на больших дисплеях подтверждается отсутствие новых ограничений со стороны приложения.

## Отклонённые альтернативы

- **Безусловные ограничения общей Activity с расчётом на Android 16.** На поддерживаемых старых ОС они затрагивают и большие экраны, нарушая телефонную границу требования.
- **`SystemChrome.setPreferredOrientations`.** Вызов выполняется после запуска движка, не запрещает разделённый экран и тоже игнорируется на больших экранах (https://api.flutter.dev/flutter/services/SystemChrome/setPreferredOrientations.html).
- **Альбомные раскладки и раскладки для половины экрана.** Каждому экрану понадобился бы второй вариант, которого нет в дизайне.
- **Закреплять календарь, только когда он помещается.** Это решает случай календаря, но не даёт правила остальным экранам и усложняет раскладку.
