# ADR-0057: Выполнять каскад по составу, подтверждённому предпросмотром

- Status: proposed
- Date: 2026-11-06
- Originating change: introduce-actions-and-intention-kinds

## Контекст

Архивирование, удаление и восстановление намерения или связи затрагивают другие намерения: вспомогательные уходят каскадом, становятся главными при выборе «только это», архивируются при удалении, если остаются без активной входящей связи, или возвращаются при восстановлении. Человек видит последствия и выбирает вариант до выполнения, а между показом и выполнением граф может измениться. Защита по ревизии графа отклоняла бы операцию при любом постороннем изменении, хотя изменение, не затрагивающее выбранный вариант, конфликтом не считается.

## Решение

**Один планировщик.** Состав каскада вычисляет одна чистая функция над индексом удержания [ADR-0056](0056-compute-intention-holding-in-per-revision-index.md); её используют и предпросмотр, и исполнение. Архивирование учитывает только активные связи и намерения, удаление — и архивные.

**Предпросмотр — отдельное чтение.** Оно возвращает составы обоих вариантов и признак, нужен ли вопрос; его же используют подсказки меню. Отказ чтения отличим от отсутствия каскада.

**Команда несёт выбор и ожидаемый состав.** Команды архивирования, удаления и восстановления намерения и связи получают обязательные выбранный вариант и ожидаемый состав; для операции без вопроса это состав, вычисленный при её запуске. Транзакция заново вычисляет выбранный вариант и сравнивает множества затронутых намерений: уходящих, ставших главными, архивируемых по инварианту, восстанавливаемых. Порядок показа и число связей не сравниваются. При расхождении команда завершается конфликтом без записи.

**Исход несёт всё изменённое.** Пакет подтверждённой команды содержит изменение каждой затронутой связи, мутацию каталога и абсолютные количества связей каждого затронутого намерения по [ADR-0011](0011-derive-relation-counts-from-graph-snapshots.md), изменение удержания и исход каскада, из которого собирается одно сообщение.

Отклонённые варианты: ответ «нужно решение» из самой команды — вносит незавершённый результат в канал координатора; защита по ревизии — ложные конфликты на посторонних изменениях; хеш состава вместо множеств — тот же результат при худшей диагностике.

## Последствия

- Координатор резервирует только сам элемент операции; корректность для остальных затронутых намерений держится на единственной очереди записи и сравнении состава в транзакции.
- После конфликта следующая попытка снова читает предпросмотр.
- Инвариант «у активного вспомогательного есть активная входящая связь» проверяется в транзакции по затронутым намерениям.
