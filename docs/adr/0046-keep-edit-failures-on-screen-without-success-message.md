# ADR-0046: Не объявлять успех правки сообщением, оставляя отказ её экрану

- Status: proposed
- Date: 2026-10-27
- Originating change: redesign-intention-page

## Контекст

По [ADR-0012](0012-centralize-graph-operation-result-presentation.md) успех принятой операции сразу принадлежит общей поверхности приложения. Отказ принадлежит открытой экранной сессии инициатора, пока жив renderer его сообщения, и переходит оболочке, когда renderer исчезает до подтверждённого кадра. [ADR-0016](0016-present-only-failure-for-self-evident-success.md) добавила политику «только отказ»: успех не образует права предъявления, а отказ сразу принадлежит общей поверхности. Она подходит операциям прямого манипулирования, у которых нет собственного renderer отказа.

Изменение `redesign-intention-page` переносит правку названия и описания намерения на отдельный экран. Успешное сохранение закрывает экран, и страница намерения сразу показывает новый текст, так что сообщение об успехе повторило бы видимое. Отказ проверки поля должен объясняться у этого поля, а отказ хранилища — оставаться на экране рядом с введённым текстом. Ни одна из двух политик этого не выражает: политика по умолчанию предъявляет успех сообщением, а «только отказ» забирает отказ у экрана.

## Решение

`GraphCommandCoordinator` получает третью политику предъявления — «успех без сообщения».

- Успех операции с этой политикой публикуется в канал завершений для согласования данных, но не образует права предъявления.
- Отказ следует протоколу ADR-0012 без изменений: он принадлежит инициатору, пока его renderer в дереве, и переходит оболочке при исчезновении renderer до подтверждённого кадра или при уходе экранной сессии.

Политику по-прежнему задаёт вид операции в координаторе; экран и модель её не выбирают. Политика допустима, только когда выполнены оба условия:

- спецификация операции прямо запрещает сообщение об успехе;
- успешный результат виден в данных представления, к которому возвращается пользователь.

Первая такая операция — изменение названия и описания намерения.

## Последствия

- Координатор различает три политики: по умолчанию, «только отказ» и «успех без сообщения». Правило однократного предъявления действует для всех отказов и для успехов политики по умолчанию.
- Успешное завершение операции с новой политикой не оставляет в координаторе непредъявленной записи. Проверки координатора закрепляют это отдельно от политики «только отказ».
- Если пользователь ушёл с экрана до успеха, сообщения нет: результат виден в данных при возвращении. Отказ после ухода предъявляет оболочка.
- Будущие экраны правки существующих сущностей получают эту политику только через свою спецификацию.

## Отклонённые альтернативы

- **«Только отказ» с проверкой полей в модели до отправки.** Предметная проверка дублируется вне границы графа, а отказ хранилища уходит с открытого экрана и теряет контекст введённого текста.
- **Подавление сообщения об успехе в презентере.** Право предъявления остаётся неподтверждённым, а решение о показе принимает поверхность, а не координатор. ADR-0016 отклонила это по той же причине.
- **Сообщение об успехе по политике по умолчанию.** Оно повторяет видимый результат и занимает очередь общей поверхности.
