# ADR-0016: Предъявлять только отказ операции, успех которой виден в согласованных данных

- Status: proposed
- Originating change: add-home-navigation-and-favorites
- Date: 2026-10-02

## Контекст

По [ADR-0012](0012-centralize-graph-operation-result-presentation.md) каждый результат принятой операции получает право предъявления: успех сразу принадлежит общей поверхности, а ошибка — открытой экранной сессии инициатора. Сообщения общей поверхности показываются строго по одному.

Перестановка избранных намерений — операция прямого манипулирования. Её успех человек видит как новый порядок списка, а отдельное сообщение на каждое перемещение заполняло бы общую очередь. Отказ при этом нужно предъявить и тогда, когда страница-инициатор не видна. По [ADR-0014](0014-host-primary-navigation-in-root-page-shell.md) невыбранная корневая страница остаётся в дереве, поэтому её renderer удерживал бы право предъявления бессрочно.

Этот ADR дополняет ADR-0012 и не заменяет его: владение поверхностями, claims, очерёдность и свидетельство кадра сохраняются.

## Решение

`GraphCommandCoordinator` получает политику предъявления, определяемую видом операции.

- По умолчанию действует протокол ADR-0012 без изменений.
- Для операции с политикой «только отказ» успех публикуется в канал завершений для согласования данных, но не образует права предъявления. Отказ сразу принадлежит общей поверхности, без права инициатора.

Политику задаёт тип завершения в координаторе. Экран и view model не выбирают и не меняют её. Политика «только отказ» допустима, только когда подтверждённый результат виден в согласуемых данных инициировавшего представления и спецификация операции прямо требует не показывать сообщение об успехе. Первая такая операция — перестановка избранных намерений.

## Последствия

- Правило «каждый результат предъявляется ровно один раз» действует для операций с политикой по умолчанию; для политики «только отказ» оно действует для отказов.
- Очередь общей поверхности не получает успехов прямого манипулирования и не задерживает ими остальные сообщения.
- Предъявление отказа такой операции не зависит от видимости инициатора; инлайн-сообщение для него не используется.
- Успешное завершение такой операции не оставляет в координаторе непредъявленной записи. Это закрепляется проверками координатора.
- Новая операция получает политику «только отказ» только через свою спецификацию. Если подтверждённый результат не виден в согласуемых данных, действует политика по умолчанию.

## Отклонённые альтернативы

- Сообщение об успехе каждой перестановки: очередь из сообщений, повторяющих уже видимый результат.
- Инлайн-ошибка на странице-инициаторе: скрытая корневая страница удерживает право и не предъявляет отказ до возвращения.
- Подавление сообщения в presenter: право предъявления остаётся неподтверждённым, и решение о показе принимает поверхность, а не координатор.
