# ADR-0015: Вести ручной порядок избранных намерений явными местами целого списка

- Status: proposed
- Originating change: add-home-navigation-and-favorites
- Date: 2026-10-02

## Контекст

Избранные намерения образуют единый порядок, который человек меняет вручную. Вновь отмеченное намерение встаёт в конец, архивированное сохраняет место, а отметка не является редактируемым полем намерения.

Существующие источники порядка для этого не подходят. [ADR-0006](0006-treat-device-clock-timestamps-as-observations.md) запрещает выводить порядок из показаний часов, [ADR-0003](0003-use-typed-uuid-identifiers-for-domain-entities.md) — из идентификатора, а ревизия графа из [ADR-0009](0009-unify-personal-graph-module-and-revision.md) не сохраняется. [ADR-0010](0010-persist-long-term-relation-creation-order.md) хранит неизменяемый порядок создания, тогда как ручной порядок изменяем.

ADR-0009 не включает в границу личного графа неограниченные чтения. [ADR-0013](0013-load-complete-tag-snapshots.md) сделал исключение для небольших списков тегов. Перестановка требует списка целиком: место намерения определяется относительно остальных, включая скрытые архивированные.

## Решение

Отметка избранного — строка отдельной таблицы, ссылающаяся на намерение с каскадным удалением. Наличие строки и есть отметка. Место в порядке — уникальное положительное целое этой строки. Место не является полем намерения, не обязано быть плотным и не служит идентичностью.

Отметка получает место после текущего максимума. Снятие отметки и удаление намерения оставляют пропуск. Перестановка в одной транзакции переписывает места всех избранных намерений в новом порядке. Правило перестановки выражается над полным порядком, включая архивированные намерения, одной чистой функцией, общей для всех адаптеров границы.

Список избранных намерений читается целиком одним согласованным снимком на одной ревизии, без курсоров, размера порции и искусственного предела — по образцу ADR-0013. Каталог намерений и остальные чтения графа остаются порционными по ADR-0009.

Порядок не выводится из времени, идентификатора, ревизии графа или других данных намерения.

## Последствия

- Отметку без места, место без отметки, вторую отметку одного намерения, отметку отсутствующего намерения и два намерения на одном месте исключает сама схема.
- Перестановка не пишет в строки намерений: их временные метки и поисковая проекция не затрагиваются.
- Стоимость чтения и перестановки линейна по числу избранных намерений. Это принимается для списка, который человек ведёт вручную; изменение ожидаемого масштаба потребует пересмотра представления порядка и способа чтения.
- После публикации схемы представление места становится долговечным: его замена требует миграции по [ADR-0002](0002-use-drift-sqlite-for-local-graph.md).
- Места описывают порядок одного локального хранилища. Импорт и синхронизация должны отдельно определить объединение порядков разных источников.

## Отклонённые альтернативы

- Столбец места в таблице намерений: перестановка писала бы в строки намерений и смешивала отметку с редактируемыми полями.
- Дробные или строковые ключи между соседями: перестановка меняет одну строку, но требует алгоритма ключей; преимущество проявляется при синхронизации, которой нет.
- Связный список со ссылкой на предыдущее намерение: чтение требует рекурсии, а перестановка — согласованного изменения нескольких ссылок.
- Порционное чтение с курсором: перестановка и скрытые архивированные намерения всё равно требуют полного порядка.
