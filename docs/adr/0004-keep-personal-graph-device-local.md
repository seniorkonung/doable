# ADR-0004: Хранить текущий граф во внутреннем хранилище Android

- Status: proposed
- Originating change: manage-intentions
- Date: 2026-08-28

## Контекст

Названия и описания намерений могут содержать личную информацию. Capability задаёт платформонезависимую долговечность в пределах одной установки приложения и запрет неуправляемого системного backup/transfer. Этот ADR фиксирует реализацию политики только для текущего Android host adapter: change не включает cloud backup, device-to-device transfer, экспорт, синхронизацию или согласие на передачу данных за пределы установки. Android Auto Backup и device-to-device transfer способны переместить database автоматически, хотя пользователь ещё не получил управляемую модель переноса и восстановления. Manifest merge также способен добавить запрос permission из транзитивной Android-зависимости; текущий release получает от AndroidX Core собственное package-разрешение для защиты неэкспортируемых динамических receivers на старых версиях Android.

## Решение

Android host adapter размещает SQLite database, WAL и временные файлы только во внутреннем app-specific storage. Для текущего release полный утверждённый набор запрашиваемых packaged permissions состоит ровно из принадлежащего package разрешения `software.doable.doable.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`; тот же packaged manifest объявляет его с уровнем защиты `signature`. Любой другой `uses-permission` или `uses-permission-sdk-23`, включая `INTERNET`, системное или стороннее разрешение и разрешение внешнего хранилища либо media, не утверждён. Расширение или иное изменение этого набора требует отдельного явного продуктового решения и согласованного пересмотра privacy contract; обязательный gate проверяет итоговый manifest release APK по exact allowlist и завершается ошибкой при неизвестном или неполном evidence. Database явно исключается из cloud backup и device-to-device transfer правилами `data-extraction-rules` для Android 12+ и `full-backup-content` для Android 11 и ниже.

Эта конфигурация ограничивает системные способы копирования данных и не реализует синхронизацию. Совместимые обновления сохраняют данные существующей установки, но новая установка после удаления приложения, очистки данных или утраты устройства не получает прежний граф. Решение не запрещает будущую управляемую синхронизацию через прикладные границы системы.

Шифрование SQLite на уровне приложения и app lock не добавляются: без отдельного пользовательского секрета ключ доступен тому же процессу и не защищает от полностью скомпрометированного разблокированного устройства, но создаёт риск необратимой потери данных. Модель угроз должна быть пересмотрена до появления синхронизации, экспорта, общего устройства или app lock.

## Последствия

- Текущий change не создаёт неявных сетевых или backup-копий личного графа.
- Изменение manifest приложения или зависимости, добавляющее, удаляющее либо заменяющее packaged permission, останавливает release gate до явного пересмотра утверждённого набора; новые Android permission names не наследуют разрешение автоматически.
- Удаление приложения, очистка его данных или потеря устройства приводят к потере локального графа; обещание долговечности ограничено перезапусками и совместимыми обновлениями одной установки.
- Sandbox и шифрование внутреннего хранилища Android являются базовой, но не абсолютной защитой от доступа к данным.
- Решение не определяет storage, backup или transfer adapter другой платформы; её реализация должна соблюдать ту же capability-политику и получить собственное platform evidence.
- Будущая синхронизация должна явно определить согласие пользователя, разрешение конфликтов и восстановление, не раскрывая эти решения в текущем локальном storage adapter.
