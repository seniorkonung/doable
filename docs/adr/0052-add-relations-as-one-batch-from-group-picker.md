# ADR-0052: Добавлять связи одной пачкой из поиска группы

- Status: proposed
- Date: 2026-11-01
- Originating change: add-relations-in-batches

## Контекст

Человек декомпозирует намерение пачками, находясь на его странице. Форма одной связи и режим быстрого создания этому не соответствовали. Новый сценарий добавляет сразу несколько связей в группу, а панель создания намерения вызывается прямо из поиска и не должна уводить из него.

Запись [ADR-0022](0022-complete-creation-flows-within-owned-route-boundaries.md) задаёт поток создания, который заменяет свой корень подробным просмотром созданной сущности. Для пачки такого просмотра нет. Запись [ADR-0050](0050-mark-occupied-pairs-in-same-catalog-page.md) вводит пробу пары с изменяемой связью и занимающую связь без типа. Изменяемой связи больше нет, а причина занятости зависит от типа. Запись [ADR-0020](0020-host-persistent-navigation-in-ordinary-page-scaffolds.md) выбирает каркас страницы по типизированному контексту открытия, но над поиском могут открываться разные страницы, и панель навигации на любой из них стёрла бы отметки сбросом истории. Эти записи пересматриваются частично, их остальные решения сохраняются. Их исходные изменения уже находятся в архиве, поэтому записи не правятся.

## Решение

**Одна команда на пачку.** Команда принимает намерение страницы, группу и упорядоченный непустой набор разных намерений. Она выполняется одной транзакцией: создаются все связи или ни одна. Порядок набора становится порядком создания. Приоритет P4 и отсутствие описания — правило операции, а не её параметры. Завершение несёт изменение на каждую связь на одной ревизии.

**Создание связи не открывает сущность.** Поток добавления завершается возвратом на группу страницы. Правило ADR-0022 о замене корня созданной сущностью для связей больше не действует и сохраняется для намерения; для действия правило пересмотрено ADR-0058. Страница намерения узнаёт о результате только из завершения команды.

**Отметки принадлежат экземпляру поиска.** Они не становятся черновиком сущности, живут в модели экземпляра страницы по [ADR-0028](0028-scope-opening-parameter-state-to-page-instances.md) и согласуются завершениями команд.

**Над поиском нет панели навигации.** Правило определяется положением страницы: каркас обычной страницы не показывает панель, а страница намерения не предлагает добавление связей и создание действия, только если маршрут поиска участника лежит в корневом стеке ниже маршрута самой страницы. Страница под поиском, в том числе открывшая его, всегда сохраняет панель и «Добавить». Правило выводится из самого стека, а не передаётся через переходы. Положение страницы относительно поиска не меняется за её жизнь, поэтому подписка на изменения стека не нужна. Новых связей, пока поиск открыт, не возникает.

**Вспомогательное создание возвращает результат своей задаче.** Панель создания намерения получает закрытый контекст запуска. Запуск из поиска завершается возвратом в этот поиск с отметкой нового намерения и не открывает его страницу. Панель остаётся одной модальной сессией по [ADR-0018](0018-manage-modal-creation-sessions-in-root-stack.md).

**Проба пары проще.** Проба всегда принадлежит группе и не знает об изменяемой связи, а занимающая связь несёт тип. Способ вычисления занятости в снимке порции и согласование фактами из ADR-0050 сохраняются.

## Последствия

- Новый массовый сценарий получает образец: команда на всю пачку, один пакет фактов и одно сообщение со счётчиком.
- Будущее множественное выделение может повторить этот подход для операций над несколькими связями.
- Отказ одной пары отменяет всю пачку. Модель поиска заранее снимает отметки, которые перестали быть допустимыми, поэтому такой отказ редок.
- Панель создания намерения зависит от закрытого контекста запуска: новому вызывающему нужен новый вариант, а не флаги.
- Каркас обычной страницы знает об одном маршруте-задаче. Если такое правило понадобится другой задаче, его стоит обобщить вместе с ней.

## Отклонённые альтернативы

- Несколько команд создания подряд: частичный успех, несколько ревизий и несколько сообщений.
- Открывать созданные связи после добавления: подробного просмотра пачки нет, а результат виден в группе.
- Возвращать созданное намерение только результатом маршрута: операция и её предъявление принадлежат координатору, а результат маршрута теряется при уходе.
- Проверять наличие поиска в стеке и подписать страницы на изменения стека: это сложнее и может давать мигание панели при закрытии поиска.
