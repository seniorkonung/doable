# ADR-0035: Переносить данные графа в предметном версионируемом формате

- Status: proposed
- Originating change: add-graph-export-import
- Date: 2026-10-17

## Контекст

Файл экспорта должен импортироваться любой будущей версией Doable, даже спустя годы. Суть данных графа меняется редко, а схема хранения — часто. Тот же формат нужен снимкам лога фактов ([ADR-0034](0034-record-confirmed-graph-changes-in-local-fact-log.md)) и будущим пакетам синхронизации ([ADR-0038](0038-sync-devices-through-thin-encrypted-file-server.md)).

Импорт файла SQLite расширил бы границу доверия, которую [ADR-0008](0008-treat-sqlite-schema-functions-as-durable-contract.md) ограничивает собственным внутренним файлом. Стандартная библиотека Dart не умеет разбирать один большой документ JSON потоково, а объём графа ограничен только местом на устройстве.

## Решение

Формат описывает сущности в терминах предметной области и не зависит от схемы базы. Виды записей: теги, намерения, назначения тегов, долговременные связи, дневные выборы с путями и, только в пакетах, удаления.

Файл — gzip поверх текста UTF-8 в формате JSON Lines. Первая строка — заголовок с маркером Doable, версией формата, моментом и количеством записей каждого вида. Дальше идут секции в фиксированном порядке, и каждая запись ссылается только на предшествующие строки. Внутри секции записи следуют в порядке создания. Количества сверяются при чтении, поэтому файл, обрезанный по границе строки, не принимается за исправный. Запись каноническая: одно состояние всегда даёт одни и те же байты.

Версия формата — целое число. Она меняется при изменении состава или смысла данных и только тогда.
- Повышение версии — построчные чистые функции. Они не удаляются, поэтому текущая версия читает любую ранее опубликованную.
- Версию несёт каждый носитель записей: файл и снимок — в заголовке, пакет лога фактов — в своей строке. Записи любого носителя повышаются от его версии одной цепочкой, поэтому хранимые снимки и пакеты при смене формата не переписываются.
- Если правило данных ужесточается, повышение применяет то же преобразование, что и миграция базы.
- Чтение каждой опубликованной версии проверяется до признания сборки готовой на неизменяемых эталонах: файле и пакете фактов со всеми видами записей, включая удаление.
- Файл более новой версии не читается.

Модуль формата не зависит от Flutter и SQLite.

## Последствия

- Изменения схемы базы, не меняющие сути данных, формат не затрагивают.
- Изменение сути данных требует новой версии формата, функции повышения и эталонов.
- Новый вид данных графа встаёт в порядок секций так, чтобы ссылаться только на предшествующие. Повышение, которому нужен весь файл, придётся выполнять уже в базе после загрузки, а не построчно.
- Файл можно распаковать и прочитать стандартными инструментами. Он не защищён: модель угроз — в [ADR-0037](0037-export-unencrypted-file-through-system-dialogs.md).
- Импорт сохраняет относительный порядок файла как локальный порядок создания: при замене графа объединять порядки источников по [ADR-0010](0010-persist-long-term-relation-creation-order.md) не нужно.

## Отклонённые альтернативы

- Файл базы SQLite: зависит от схемы хранения и расширяет границу доверия ADR-0008.
- Один документ JSON: для ограниченной памяти нужен собственный потоковый разборщик.
- Формат без версий, только с добавлением полей: смысл данных тоже может меняться, а старое приложение молча теряло бы то, чего не понимает.
- Пакеты лога без версии с перезаписью миграцией базы при смене формата: формат оказался бы связан со схемой хранения, а ошибка повышения остановила бы запуск приложения.
- CSV и бинарные форматы: CSV плохо выражает пути и типы, бинарные форматы теряют читаемость.
