# ADR-0024: Вычислять состояния дней календаря агрегатом сохранённых действий

- Status: proposed
- Originating change: add-daily-choice-calendar-day-marks
- Date: 2026-10-12

## Контекст

Календарь экрана дня показывает состояние каждого видимого дня: все действия этой даты выполнены, среди них есть невыполненное или таких действий нет. Состояние зависит от всех действий даты. Оно меняется при создании, переносе даты, переключении выполнения и удалении, а в будущем — и при новых операциях с действиями. Отметки видимого и соседних периодов нужны сразу. Загрузка полных действий с путями ради них нарушила бы ограниченное чтение по [ADR-0009](0009-unify-personal-graph-module-and-revision.md).

Хранимая сводка по датам потребовала бы поддержки в каждой команде, миграции с заполнением и проверки согласованности. [ADR-0011](0011-derive-relation-counts-from-graph-snapshots.md) по тем же причинам выбрала агрегаты для счётчиков, но её область ограничена долговременными связями.

## Решение

Источником истины для состояния дня служат сами сохранённые действия. Состояния вычисляются агрегатом внутри SQLite по дате и выполнению для ограниченного диапазона дат. Они не сохраняются отдельной таблицей или полями и не переживают процесс приложения. `PersonalGraphRepository` возвращает состояния только тех дней, на которые есть действия, вместе с ревизией снимка; отсутствие дня в результате означает, что действий нет. Длина диапазона ограничена контрактом запроса.

Отметки согласуются повторным чтением, а не применением изменений в памяти. Представление перечитывает свой диапазон после каждой новой подтверждённой ревизии графа и не разбирает виды изменений в пакете. Ответ, который старее известной ревизии, отбрасывается по протоколу ADR-0009. Недопустимая сохранённая дата или недопустимое значение выполнения дают отказ всего чтения: частичного результата и ложного отсутствия действий нет. Категория отказа записывается в диагностику без пользовательского содержимого.

## Последствия

- Новые и изменённые операции с действиями не поддерживают второе представление. Отметки отражают их автоматически, пока операции проходят через координатор.
- Каждая подтверждённая команда, в том числе не связанная с действиями, вызывает одно ограниченное агрегатное чтение, пока экран дня открыт.
- Стоимость чтения растёт с числом действий в диапазоне, а не с размером графа. Покрывающий индекс, если его потребуют измерения, — изменение схемы без второго источника истины. Материализованная сводка потребует отдельного решения о согласованности, миграциях и восстановлении.
- Агрегат не проверяет пути действий: их повреждение обнаруживают чтения, которые пути используют.
