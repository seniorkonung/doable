# ADR-0024: Вычислять состояния дней календаря агрегатом сохранённых дневных выборов

- Status: proposed
- Originating change: add-daily-choice-calendar-day-marks
- Date: 2026-10-12

## Контекст

Календарь каталога дневных выборов показывает состояние каждого видимого дня: все связи «я сегодня» этой даты выполнены, среди них есть невыполненная или таких связей нет. Состояние зависит от всех выборов даты. Оно меняется при создании, переносе даты, переключении выполнения и удалении, а в будущем — и при новых операциях с дневными выборами. Отметки видимого и соседних периодов нужны сразу. Загрузка полных выборов с путями ради них нарушила бы ограниченное чтение по [ADR-0009](0009-unify-personal-graph-module-and-revision.md).

Хранимая сводка по датам потребовала бы поддержки в каждой команде, миграции с заполнением и проверки согласованности. [ADR-0011](0011-derive-relation-counts-from-graph-snapshots.md) по тем же причинам выбрала агрегаты для счётчиков, но её область ограничена долговременными связями.

## Решение

Источником истины для состояния дня служат сами сохранённые дневные выборы. Состояния вычисляются агрегатом внутри SQLite по дате и выполнению для ограниченного диапазона дат. Они не сохраняются отдельной таблицей или полями и не переживают процесс приложения. `PersonalGraphRepository` возвращает состояния только тех дней, на которые есть выборы, вместе с ревизией снимка; отсутствие дня в результате означает, что выборов нет. Длина диапазона ограничена контрактом запроса.

Отметки согласуются повторным чтением, а не применением изменений в памяти. Представление перечитывает свой диапазон после каждой новой подтверждённой ревизии графа и не разбирает виды изменений в пакете. Ответ, который старее известной ревизии, отбрасывается по протоколу ADR-0009. Недопустимая сохранённая дата или недопустимое значение выполнения дают отказ всего чтения: частичного результата и ложного отсутствия выборов нет. Категория отказа записывается в диагностику без пользовательского содержимого.

## Последствия

- Новые и изменённые операции с дневными выборами не поддерживают второе представление. Отметки отражают их автоматически, пока операции проходят через координатор.
- Каждая подтверждённая команда, в том числе не связанная с дневными выборами, вызывает одно ограниченное агрегатное чтение, пока каталог открыт.
- Стоимость чтения растёт с числом выборов в диапазоне, а не с размером графа. Покрывающий индекс, если его потребуют измерения, — изменение схемы без второго источника истины. Материализованная сводка потребует отдельного решения о согласованности, миграциях и восстановлении.
- Агрегат не проверяет пути выборов: их повреждение обнаруживают чтения, которые пути используют.
