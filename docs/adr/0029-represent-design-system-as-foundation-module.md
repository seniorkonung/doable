# ADR-0029: Представлять дизайн-систему Doable модулем основ оформления

- Status: proposed
- Originating change: add-design-foundation
- Date: 2026-10-14

## Контекст

Для Doable готова дизайн-система: цвета светлой и тёмной тем, стили текста на Inter, шкалы отступов и радиусов, правила компонентов. Экраны будут переводиться на неё по одному. До этого изменения приложение не задавало тему: экраны собраны из виджетов Material и читают роли `ColorScheme` и `TextTheme`.

Материалы дизайна приватны, в репозитории их нет, и CI их не видит.

Release-сборка не имеет разрешения на сеть по [ADR-0004](0004-keep-personal-graph-device-local.md), а дизайн-система подключает Inter из Google Fonts.

Советы дизайн-системы по переносу во Flutter частично расходятся с используемой версией Flutter. Вес вариативного шрифта там задаётся через `FontVariation`, а во Flutter 3.47.1 `FontWeight` сам выставляет ось `wght`, тогда как явная вариация перекрывает вес.

Без общей границы каждый экран и компонент выбирал бы цвета, шрифты и размеры сам, и переход растянулся бы на разнородные значения.

## Решение

**Модуль.** Модуль `lib/src/design_system/` — единственный владелец значений дизайн-системы в коде и место будущих компонентов дизайн-системы. Значения переносятся из материалов дизайна вручную, имена повторяют имена токенов. Компоненты дизайн-системы и экраны, переводимые на дизайн, берут цвета, стили текста, отступы и радиусы из модуля, а не задают свои значения. Существующие экраны сохраняют свои отступы, пока их не переведут.

**Токены.**
- Цвета — расширение темы `DoableColors` с экземплярами для светлой и тёмной тем; алиасы дизайн-системы — вычисляемые свойства.
- Стили текста — `DoableType`, без цвета.
- Палитра, стили текста и шкалы отступов и радиусов переносятся целиком: по решению владельца продукта фундамент сразу определяет все основы дизайна.
- Наборы токенов перечислены по одному разу, и компилятор требует значение каждого токена.
- Размеры отдельных компонентов и тени появляются вместе с первым компонентом, которому они нужны.

**Темы.** Модуль строит светлую и тёмную `ThemeData`:
- роли `ColorScheme` и `TextTheme` выводятся из токенов;
- `primary` — это `ink`, цвет основной кнопки дизайн-системы;
- оформляются только виджеты Material, которые приложение использует.

Оба `MaterialApp` приложения получают обе темы и следуют системной настройке оформления.

**Шрифт.** Inter поставляется вместе с приложением одним вариативным файлом прямого начертания.
- Вес задаётся только через `FontWeight`.
- Оптический размер задаётся явно, по кеглю в логических пикселях, как в макетах.
- Символы вне набора Inter берутся из шрифтов устройства.

**Размеры.** Размеры из дизайна трактуются как минимальные; масштаб текста не ограничивается.

## Последствия

- Перевод экранов опирается на один источник значений; изменение значения в дизайне правится в одном месте.
- Повторный экспорт дизайна сверяется вручную: значения нового экспорта сравниваются со значениями модуля. Автоматической проверки соответствия нет, потому что материалы приватны.
- Пока экраны не переведены, выбранные состояния существующих виджетов, которые читают `primary`, рисуются цветом `ink`, а не акцентом.
- Новый цвет — правка модуля. Полноту `copyWith`, `lerp` и списков токенов обеспечивает построение, а не отдельные проверки.
- Текстовый шрифт увеличивает release APK: Flutter не урезает текстовые шрифты.
- Обновление Flutter может изменить значения Material по умолчанию. Для используемых виджетов они заданы явно.
- Если совет дизайн-системы расходится с ADR проекта или с используемой версией Flutter, компоненты следуют решениям проекта.

## Отклонённые альтернативы

- **Генератор из `tokens.json`.** Материалы приватны и недоступны в CI, а инструмент понадобился бы ради примерно 60 редко меняющихся значений.
- **`primary` = `accent`.** Выбранные состояния были бы ближе к дизайну, но пришлось бы переопределять `FilledButton`, что задевает и `FilledButton.tonal`, и индикаторы загрузки.
- **Пакет `google_fonts`.** Загрузка во время работы невозможна без разрешения на сеть, а с локальными ассетами пакет становится лишней зависимостью.
- **Статические файлы по весам.** В них нет веса 650 и оси `opsz`.
- **Системный шрифт.** Противоречит дизайн-системе.
- **Тема внутри `lib/src/app/`.** Связала бы будущие общие компоненты со сборкой приложения.
