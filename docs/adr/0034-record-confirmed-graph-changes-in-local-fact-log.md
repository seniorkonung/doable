# ADR-0034: Записывать подтверждённые изменения графа в локальный лог фактов

- Status: proposed
- Originating change: add-graph-export-import
- Date: 2026-10-17

## Контекст

Экспорт должен отражать одно состояние графа, не занимая единственное соединение с базой на всё время выгрузки. Резервные копии должны возвращать граф к любому из сохранённых состояний за последние 7 дней. Будущая синхронизация будет переносить изменения пакетами (ADR-0038). Ни одна из этих возможностей не должна заново читать всю базу.

[ADR-0009](0009-unify-personal-graph-module-and-revision.md) оставляет `GraphRevision` эфемерной и запрещает долговечные ревизии и метаданные «без собственного поведения». У лога фактов это поведение есть сразу: на нём строятся экспорт и резервные копии.

Запись в графе идёт восемью отдельными блоками репозитория, а каскады внешних ключей коду команд не видны: удаление тега удаляет его назначения, удаление дневного выбора — шаги пути.

## Решение

Каждое подтверждённое изменение графа в той же транзакции SQLite записывается пакетом фактов. Факт — это полное состояние затронутой сущности после транзакции в записи формата [ADR-0035](0035-keep-graph-data-in-versioned-domain-format.md) или её удаление.

Полноту захвата обеспечивает схема. Постоянные триггеры на таблицах графа отмечают затронутые сущности и запоминают первую операцию, в том числе при каскадных удалениях. Все записи репозитория проходят через единый внутренний путь. Перед COMMIT он превращает отметки в пакет и требует, чтобы отметок не осталось. Выключать захват может только замена графа ([ADR-0036](0036-replace-graph-atomically-with-new-epoch-and-generation.md)).

У пакета неизменяемая неповторяющаяся позиция в пределах установки (`AUTOINCREMENT`) и время записи по часам устройства. Время — наблюдение ([ADR-0006](0006-treat-device-clock-timestamps-as-observations.md)). Позиция не заменяет `GraphRevision`: ревизия остаётся эфемерной, а согласование представлений по ADR-0009 не меняется.

Состояние на любой хранимой позиции собирается из ближайшего снимка не новее неё и пакетов после него. Снимок — неизменяемый файл формата ADR-0035 вне базы. Он регистрируется в базе только после надёжной записи, а при чтении проверяется контрольной суммой. Лог сжимается в снимки фоном, из файлов и пакетов, без длинных транзакций. Резервная копия — сохранённая позиция, и срок хранения копий определяет, какие снимки и пакеты нужны.

## Последствия

- Каждая команда пишет больше: отметки и пакет фактов. Цену измеряет бенчмарк.
- Новая таблица графа обязана получить триггеры захвата, а новая сущность — запись формата. Пропуск обнаруживает контрольная проверка: выгрузка базы совпадает с состоянием, собранным из снимка и лога.
- Резервная копия не копирует данные, а экспорт не держит соединение.
- Будущая синхронизация отправляет те же пакеты. Глобальный порядок задаст сервер (ADR-0038), локальная позиция его не обещает.
- Файлы снимков вне SQLite журналом не защищены. Повреждённый снимок обнаруживается при чтении, а текущий граф в базе остаётся целым.

## Отклонённые альтернативы

- Факты в коде каждой команды: пути записи и каскады внешних ключей легко пропустить.
- Лог в файлах: при падении между COMMIT и записью файла он расходится с базой.
- Временные триггеры соединения: их пришлось бы ставить на каждом соединении, а временные таблицы этой сборки SQLite живут в памяти.
- Копия как полная выгрузка: каждый раз полное чтение базы и блокировка единственного соединения.
- Режим WAL с соединениями чтения: чтение перестало бы мешать работе, но копия всё равно оставалась бы полным чтением.
