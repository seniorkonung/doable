# ADR-0054: Показывать и менять дневной выбор в одном листе без маршрута

- Status: proposed
- Date: 2026-11-01
- Originating change: redesign-daily-choices

## Контекст

Подробный просмотр дневного выбора и форма его изменения были отдельными маршрутами. Дизайн заменяет их одной нижней панелью: дата, время, приоритет и выполнение меняются сразу, без кнопки сохранения, описание сохраняется кнопкой внутри листа, а создание закрывает поток и не открывает созданный выбор.

Запись [ADR-0022](0022-complete-creation-flows-within-owned-route-boundaries.md) требует заменять корень потока создания подробным просмотром созданной сущности. [ADR-0052](0052-add-relations-as-one-batch-from-group-picker.md) уже сняла это правило для связей и оставила его для намерения и дневного выбора. У листа нет маршрута, на который можно заменить корень, поэтому для дневного выбора правило больше не выполнимо.

Запись [ADR-0020](0020-host-persistent-navigation-in-ordinary-page-scaffolds.md) делит экраны на обычные страницы и страницы-задачи, а [ADR-0032](0032-present-design-system-sheets-over-root-navigator.md) задаёт только показ листа. Страницы поверх листа эти записи не описывают, хотя путь выбора ведёт на страницы своих намерений.

Абзац ADR-0022 о замене пути тоже больше не действует: изменение `redesign-daily-choices` убирает замену из приложения. Другой путь — это новый выбор. Это поведение приложения, а не инвариант хранилища, поэтому схема его не закрепляет.

## Решение

**Лист без маршрута.** Подробный просмотр дневного выбора показывает одна функция приложения через показ листа из ADR-0032. Маршрута у него нет, поэтому открыть выбор может только код экрана, а не переход по маршруту. Вид страницы по ADR-0020 к нему не относится: он открывается над текущей страницей и перекрывает панель навигации.

**Лист — единственное место изменения, кроме флажка карточки.** Отдельных экранов изменения выбора нет. Выполнение меняется ещё и флажком карточки каталога. Каждое изменение в листе — самостоятельная команда изменения полей через одну модель листа: дата, время, приоритет и выполнение пишутся сразу, а описание — кнопкой «Сохранить» внутри листа. Успех не объявляется по [ADR-0046](0046-keep-edit-failures-on-screen-without-success-message.md), а отказ следует протоколу [ADR-0012](0012-centralize-graph-operation-result-presentation.md). Новые действия с выбором добавляются в этот лист.

**Создание дневного выбора не открывает сущность.** Поток создания удаляет свои страницы и показывает страницу, с которой начат, а результат называет общая поверхность. Граница потока и остальные гарантии ADR-0022 сохраняются. Правило о замене корня созданной сущностью теперь относится только к намерению.

**Страница поверх листа.** Лист не закрывается, когда с него открывают страницу: страница ложится в корневой стек над безымянным маршрутом листа, а возврат показывает лист с прежним состоянием. Сброс истории снимает лист вместе со страницей, над которой он открыт.

## Последствия

- Строка дат, дублирование и другие действия с выбором попадают в лист и не требуют новых маршрутов.
- Открыть выбор переходом извне, например из уведомления, можно только через показ листа над какой-либо страницей. Если такой вход понадобится, его придётся проектировать заново.
- Каждое поле пишется отдельной командой, поэтому связанное изменение двух полей не атомарно. Интерфейс таких изменений не предлагает.
- Проверки верхнего маршрута учитывают, что лист сверху делает верхний маршрут безымянным, а страница над листом снова делает верхней страницу.
- Созданный выбор человек находит в каталоге или на странице намерения, и сообщение подтверждает результат, даже если выбор создан на другую дату.

## Отклонённые альтернативы

- Маршрут `auto_route`, нарисованный как лист: второй способ показа листов рядом с ADR-0032.
- Сохранить форму изменения рядом с листом: два места изменения всех полей одного выбора и общая кнопка сохранения формы, которой дизайн не предусматривает. Описание сохраняется кнопкой внутри листа, а остальные поля пишутся сразу.
- Открывать лист созданного выбора после закрытия потока: понадобился бы показ листа от имени страницы, которая не начинала этот переход, а дизайн завершает создание сообщением.
- Закрывать лист перед переходом на страницу: возврат терял бы контекст выбора.
