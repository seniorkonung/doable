# ADR-0039: Вести ручной порядок тегов дробными ключами в состоянии тега

- Status: proposed
- Originating change: add-tags-panel
- Date: 2026-10-22

## Контекст

У тегов личного графа появляется один ручной порядок. Он заменяет порядок создания во всех представлениях тегов: новый тег встаёт первым, копия — сразу после оригинала, а человек переставляет любой тег.

Порядок должен без потерь проходить локальную БД, журнал фактов, снимки, резервные копии и файл экспорта:

- Журнал фактов по [ADR-0034](0034-record-confirmed-graph-changes-in-local-fact-log.md) отмечает изменённую строку целиком и пишет её полное состояние.
- Сводка между копиями считает изменённой каждую сущность, у которой есть факт.
- Сборка состояния оставляет изменённую запись на прежнем месте секции. Поэтому порядок, который не является полем записи формата [ADR-0035](0035-keep-graph-data-in-versioned-domain-format.md), теряется при экспорте, восстановлении и пересборке снимков.
- Порции записей графа читаются по неизменному ключу строки.

Порядок нельзя выводить из часов устройства ([ADR-0006](0006-treat-device-clock-timestamps-as-observations.md)) и из идентификатора ([ADR-0003](0003-use-typed-uuid-identifiers-for-domain-entities.md)). Для избранных намерений [ADR-0015](0015-keep-favorite-order-as-explicit-whole-list-places.md) выбрала явные места целого списка и отклонила дробные ключи: их преимущество, по её доводу, проявлялось бы только при синхронизации. Избранное с тех пор удалено, а журнал фактов и сводки копий появились позже.

## Решение

Место тега — значение предметной модели `TagPosition`: строка ASCII в канонической форме дробного индекса base62. Место — поле самого тега, его записи в формате графа и строки `tags` с ограничением уникальности. Порядок тегов — сравнение ключей по кодовым единицам; для ASCII оно совпадает с сортировкой SQLite `BINARY`. Неканонический или повторяющийся ключ — повреждение данных, а не значение для исправления.

Команды задают размещение через соседей — «первым» или «после тега», — а не готовым ключом. Ключ вычисляет репозиторий в транзакции записи одной чистой функцией модуля тегов по ключам соседей, прочитанным в той же транзакции. Перестановка, создание первым и вставка копии меняют только строку своего тега.

Порядок тегов намерения выводится из места тега при чтении; место не копируется в назначения. Неизменная последовательность создания строки остаётся ключом порций записей и порядком записей в файлах, но видимого порядка тегов больше не задаёт.

Каноническую форму, разбор и генерацию ключей реализует код проекта, без внешней зависимости.

## Последствия

- Одно действие человека над порядком даёт один факт и одно изменение в сводке копии; создание тега первым не переписывает остальные теги.
- Схема БД и формат графа получают обязательное поле. После первой публикации его форма станет долговечным контрактом по [ADR-0002](0002-use-drift-sqlite-for-local-graph.md) и ADR-0035.
- При многократной вставке в один промежуток ключи удлиняются. Перебалансировка не вводится, потому что переписала бы все теги; если длина станет проблемой, нужен отдельный пересмотр.
- Порядок тегов в файле экспорта и при импорте задаёт поле места, а не относительный порядок записей. Относительный порядок файла по-прежнему переносит последовательность создания по ADR-0035.
- Команду с размещением через соседа можно выполнить повторно на изменившемся состоянии. Это совместимо с направлением [ADR-0038](0038-sync-devices-through-thin-encrypted-file-server.md), но решение принято не ради синхронизации: метаданных только для неё не добавляется.

## Отклонённые альтернативы

- **Явные места целого списка, как в ADR-0015.**
  - Каждая перестановка переписывает места всех тегов между старой и новой позицией, создание первым — всех тегов. Это пакет фактов и «N изменено» в сводке копии на одно действие.
  - Сдвиг мест под ограничением уникальности требует двухшаговой перезаписи.
- **Разреженные целые с перенумерацией.** Перенумерация реже, но остаётся массовой перезаписью, и добавляется правило её запуска.
- **Связный список со ссылкой на предыдущий тег.** Чтение требует рекурсии, а перестановка меняет до трёх строк.
- **Копия места в назначениях для быстрого чтения тегов намерения.** Перестановка писала бы в строки назначений, их факты относятся к намерениям, и сводка копии считала бы изменёнными все помеченные намерения.
- **Пакет дробных индексов с pub.dev.** Каноническая форма ключа становится частью формата данных, а найденные пакеты малой аудитории не гарантируют её неизменности.
