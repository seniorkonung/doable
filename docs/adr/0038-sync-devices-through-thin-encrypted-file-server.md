# ADR-0038: Синхронизировать устройства через тонкий сервер зашифрованных файлов

- Status: proposed
- Originating change: add-graph-export-import
- Date: 2026-10-17

## Контекст

Граница графа намерений — владелец, а не устройство, а дизайн продукта предусматривает синхронизацию через аккаунт. Владелец продукта требует определить её архитектуру заранее, а сервер сделать тонким: он только хранит зашифрованные файлы. Показания часов устройства не задают порядок изменений ([ADR-0006](0006-treat-device-clock-timestamps-as-observations.md)). Инварианты графа охватывают несколько сущностей: единственная связь на пару намерений, активные участники активной связи, уникальность названий тегов, непрерывность пути выбора.

Запись задаёт направление. В изменении `add-graph-export-import` синхронизация не реализуется, и метаданные только для неё не добавляются ([ADR-0009](0009-unify-personal-graph-module-and-revision.md)).

## Решение

Сервер хранит только зашифрованные устройствами файлы и поддерживает создание файла, только если такого ещё нет. Содержимого он не видит и правил графа не исполняет.

Общий лог — пронумерованные файлы пакетов фактов [ADR-0034](0034-record-confirmed-graph-changes-in-local-fact-log.md) и снимки [ADR-0035](0035-keep-graph-data-in-versioned-domain-format.md). Номер, занятый условным созданием файла, задаёт глобальный порядок, а пакеты связаны хеш-цепочкой.

Факт пишет автор команды: он выполняет её на состоянии после всех предшествующих пакетов. Остальные устройства применяют факты, проверяя только постоянные инварианты, поэтому результат не зависит от версии правил на каждом устройстве.

Неотправленные изменения устройство хранит очередью команд. Если номер уже занят другим устройством, оно применяет чужие пакеты и заново выполняет свои команды поверх них. Отклонённую команду оно объясняет человеку.

Новое устройство начинает со снимка. Замена графа на любом устройстве становится пакетом «сброс». Устройство, которое не понимает версию записей, приостанавливает синхронизацию до обновления приложения.

## Последствия

- Изменение синхронизации добавит очередь команд, шифрование и ключи, сервер и разрешение `INTERNET` с пересмотром ADR-0004. Номера общего лога станут порядком создания, который [ADR-0010](0010-persist-long-term-relation-creation-order.md) оставила на будущее. Формат и лог при этом не пересматриваются.
- Сервер может удалить, скрыть или переставить файлы. Хеш-цепочка обнаруживает пропуски и перестановки, но не скрытие последних пакетов.
- Изменение, сделанное без сети, может быть отклонено при переносе поверх чужих изменений.

## Отклонённые альтернативы

- Сервер-арбитр, который видит данные и сам сливает изменения: потом перейти к сквозному шифрованию можно только переписав протокол.
- Общий лог команд вместо фактов: устройства с разными версиями правил по-разному выполнят одну команду, и граф разойдётся.
- Логи по устройствам с логическими часами: авторы фактов не видят чужих изменений, и для каждого конфликта инвариантов нужно правило починки.
- Синхронизация состояний сущностей по правилу «последняя запись побеждает»: старое устройство стирает незнакомые поля, а нарушенные инварианты приходится чинить после слияния.
