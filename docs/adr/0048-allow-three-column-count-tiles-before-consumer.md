# ADR-0048: Поддержать три колонки CountTiles до появления потребителя

- Status: proposed
- Date: 2026-10-27
- Originating change: redesign-intention-page
- Supersedes: [ADR-0030](0030-keep-design-system-components-presentational.md) только в части появления трёхколоночной раскладки `CountTiles` до её первого потребителя.

## Контекст

ADR-0030 требует добавлять компонент дизайн-системы и его варианты вместе с потребителем. Изменение `redesign-intention-page` вводит `CountTiles` для четырёх групп «Связей» в две колонки. README компонента также описывает три колонки для «Выборов» и «Статистики», но оформление этих вкладок исключено из изменения.

Пользователь явно выбрал сохранить три колонки заранее ради будущих «Выборов» и «Статистики» и принял риск лишней реализации и сопровождения. Причина исключения должна оставаться доступной после архивации изменения, пока у варианта нет потребителя.

## Решение

В фазе 6 `redesign-intention-page` компонент `CountTiles` реализуется в двух и трёх колонках. «Связи» используют только две колонки; трёхколоночная раскладка сохраняется для будущих «Выборов» и «Статистики» без потребителя в этом изменении. Обе раскладки входят в компонентные проверки и эталоны.

Исключение ограничено этим вариантом `CountTiles`. Оно не включает оформление «Выборов» и «Статистики», другие варианты или компоненты. Остальные правила ADR-0030, включая отсутствие предметной логики в компоненте и добавление остальных вариантов вместе с потребителем, сохраняются.

## Последствия

- Реализация, проверки и сопровождение трёх колонок появляются до пользовательской пользы от этой раскладки; этот остаточный риск принят ради будущего использования.
- Объём работы и проверки обеих раскладок принадлежат существующей фазе 6; оформление исключённых вкладок не требуется.
- Расширение исключения на другой вариант, компонент или назначение требует отдельного решения. Появление реального потребителя снимает условие отсутствия потребителя.
