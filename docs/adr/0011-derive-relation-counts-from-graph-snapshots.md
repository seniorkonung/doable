# ADR-0011: Вычислять счётчики связей из согласованных снимков графа

- Status: proposed
- Originating change: manage-long-term-relations
- Date: 2026-09-13

## Контекст

Каталог, подробные данные намерений и миниатюры участников показывают точные количества непосредственных связей. Каскадное архивирование, замена участников и массовое удаление меняют несколько таких количеств одновременно. Хранимые изменяемые счётчики потребовали бы отдельной защиты от рассогласования при каждой команде и миграции. Получение всех связей в приложении ради подсчёта нарушило бы контракт ограниченного чтения. Выбор источника этих чисел влияет на будущие операции графа и стоимость его чтения.

## Решение

Источником истины для количества долговременных связей служат сами сохранённые связи. Счётчики вычисляются агрегатами внутри хранилища и не сохраняются как независимо изменяемые поля намерений или отдельная таблица. Сводка содержит восемь проверенных неотрицательных количеств по архивному состоянию, типу и направлению; итоги выводятся из них. Встречные связи учитываются отдельно, число соседних намерений не заменяет число связей.

Вычисление возвращает численные агрегаты без материализации списков предметных связей в Dart. Для каталога и миниатюр количества получаются пакетно по идентификаторам только запрошенной порции; фильтр каталога ограничивает выбранные намерения и не отсекает их соседей из подсчёта. Нулевая группа появляется только после успешного чтения и проверки результата.

По контракту [ADR-0009](0009-unify-personal-graph-module-and-revision.md) составные результаты получают одну транзакцию и ревизию: первая порция группы включает полную сводку, а продолжение той же ревизии её не пересчитывает. Подтверждённые команды возвращают абсолютные количества всех затронутых намерений, включая прежних и новых участников. Представления согласуют их по ревизии; длина загруженного списка и оптимистические приращения не подменяют полные количества. Ошибка чтения сохраняет последнее подтверждённое состояние, не выдавая его за новое.

Проверка агрегатов охватывает непосредственное соседство запрошенных намерений и возвращает агрегированный признак нарушения допустимости сохранённых данных до их исключения фильтрами. Для проверки UUID и текста применяются общие правила декодирования через закрытые чистые функции запросов. Они регистрируются через канонические границы соединений по [ADR-0002](0002-use-drift-sqlite-for-local-graph.md). Сохраняемая схема на них не ссылается, поэтому эти функции не получают долговечный статус функций схемы из [ADR-0008](0008-treat-sqlite-schema-functions-as-durable-contract.md). Повреждение возвращается типизированным отказом без частичной сводки или ложного нуля; полный аудит графа при обычном запуске не добавляется.

Счётчики остаются прикладными проекциями. Их изменение не меняет собственные данные намерения и его временные метки. Разрешение физического удаления всегда проверяется по актуальным зависимостям внутри транзакции команды, независимо от показанного количества.

## Последствия

- Новые операции графа изменяют связи и получают подтверждённые агрегаты без поддержки второго сохраняемого представления количеств.
- Стоимость агрегирования и проверки зависит от размера непосредственного соседства. Ограничение порции уменьшает материализацию строк, но не делает вычисление точного количества постоянным по времени.
- Проверки больших соседств измеряют стоимость агрегатов отдельно от получения порции и подтверждают отсутствие загрузки списков ради подсчёта.
- Если измерения потребуют материализованных счётчиков, потребуется отдельное решение о согласованности, миграциях и восстановлении с сохранением точности и внешнего контракта.
