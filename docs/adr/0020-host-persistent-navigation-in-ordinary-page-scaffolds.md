# ADR-0020: Размещать постоянную навигацию в каркасах обычных страниц

- Status: proposed
- Originating change: add-quick-creation-and-persistent-navigation
- Date: 2026-10-07
- Supersedes: [ADR-0014](0014-host-primary-navigation-in-root-page-shell.md) в части размещения панели только в оболочке и невозможности сменить пункт над корневой страницей.

## Контекст

Панель нужна на обычной странице при любой глубине истории, включая страницу намерения над незавершённой формой связи. При этом страницы-задачи должны закрывать панель, а выбор пункта — возвращать к корневой странице без сохранения отдельной истории пункта. Видимость панели больше нельзя определять принадлежностью маршрута оболочке.

ADR-0014 принадлежит уже архивированному изменению `add-home-navigation-and-favorites`, но сохраняет статус `proposed`. Эта запись предлагает пересмотр указанной части его решения; исходная запись и её статус не меняются. Оболочка корневых страниц без собственного `Scaffold`, общий корневой стек и время жизни корневых страниц сохраняются. Принятые [ADR-0012](0012-centralize-graph-operation-result-presentation.md) и [ADR-0018](0018-manage-modal-creation-sessions-in-root-stack.md) ограничивают владение сообщениями и закрытие модальной сессии создания намерения.

## Решение

Корневые страницы остаются дочерними маршрутами оболочки без собственных стеков. Остальные страницы открываются в общем корневом стеке. Обычная страница использует общий каркас с панелью в `Scaffold.bottomNavigationBar`; страница-задача строит каркас без панели. Для компонента с несколькими назначениями каркас выбирается по типизированному контексту открытия. Оболочка по-прежнему размещает панель вне корневых страниц и передаёт им нижние вставки, сохраняя их собственные `Scaffold` получателями общих сообщений.

Панель — общий компонент представления с явными состоянием и действиями. Источник выбранного пункта для всех экземпляров — маршрутизатор вкладок оболочки; источник режима быстрого создания — один контроллер приложения. Запуск быстрого создания является отдельным действием, а не пунктом навигации. Его сборка относится к приложению и зависит от входов модулей сущностей; обратная зависимость этих модулей от быстрого создания не вводится.

Выбор пункта с обычной страницы удаляет всю историю над оболочкой и выбирает корневую страницу, сохраняя её состояние. Сброс не запрашивает подтверждение потери несохранённых данных. Принятые команды продолжаются у координатора по [ADR-0009](0009-unify-personal-graph-module-and-revision.md); исчезновение поверхности ошибки обрабатывается прежним протоколом ADR-0012. Из модальной сессии создания намерения и открытых из неё страниц обычные страницы недоступны, поэтому сброс не обходит согласованное закрытие черновика по ADR-0018.

## Последствия

- Вид страницы становится обязательным решением при её подключении. Проверка состава страниц должна подтверждать выбранный каркас и размещение содержимого и сообщений над панелью.
- Несколько экземпляров панели требуют общих источников состояния. Анимация между экземплярами остаётся деталью оформления и не определяет архитектурный контракт.
- Обычная страница может сохранять под собой незавершённую задачу; сброс пунктом навигации явно завершает эту историю. Системное «назад» сохраняет обычное закрытие только верхней страницы.
- Панель вне корневого навигатора потребовала бы отдельного управления модальными барьерами и классификации всех маршрутов. Вложенный стек обычных страниц не выражает чередование обычных страниц и задач. Размещение панели в каркасе сохраняет это чередование и естественное перекрытие модальными маршрутами.
